# The route table — resolve, pin, dispatch, record, Explore

Shared by `do-next-slice` and `do-whole-phase` (one source, copied into both skills at build).

**Dispatch through the engine's route table — the decision is the engine's, never yours:** kind first (decomposition, `research` and review always route to the high row, by **kind**, whatever their `risk` says; a `co-work` mockup span too), then `risk` (exactly `low` → the mid row, `slice-executor-mid`, the default tier — real code and multi-file work included, as long as `plan.md` pins the approach — and `docs` / `qa` rated `low` → the cheap row on that same file; anything else → the high row, `slice-executor-high`), then attempt (every second attempt → high). (1) **Resolve:** once `plan.md` is written (and after `start-slice`), run `python3 scripts/workflow.py executor-route <slice_id>` — add `--retry` on a second attempt — and `python3 scripts/workflow.py executor-route --explore`. **Bump up, never down:** when the plan you write hits a named trigger (open design, a core invariant, an unlocated root cause, a wide blast radius) on a slice rated `low`, set `risk` to `high` in its `slice.json` (that one field; `python3 scripts/workflow.py rebuild` regenerates the table), say why in `plan.md`, and resolve again; never lower a rating. (2) **Pin:** append a final `## Dispatch` section to the slice's `plan.md` holding the slice form's lines verbatim (`route=` … `attribution=`) plus the `--explore` form's `model=` / `effort=` renamed `explore_model=` / `explore_effort=` — the executor copies its `model` / `effort` into its verdict block from there and takes its `Explore` lookup model from it; on a retry the new lines go under the `## Escalation: mid → high` section instead. (3) **Dispatch:** the Agent tool, as a background task, `subagent_type` = the `subagent_type=` line; pass `model` (the `model=` line, an Agent-tool alias) only when `pass_model=yes`, and `effort` (the `effort=` line) only when `pass_effort=yes`. A `fallback=` line is informational (`model=` already carries the fallen-back model); relay every `warning=` line to the operator in your report — it means the per-dispatch value will not take effect on this machine. The prompt stays the slice id, its folder and the repo root. (4) **Record:** after the completion notification — before `finish-slice`, so the record rides in the slice's commit — run `python3 scripts/workflow.py record-dispatch <slice_id> --route <route=> --tier <tier=> --model <model=> --effort "<effort=>" --verdict <done|escalate|needs_operator|blocked|failed> --attempt <attempt=> --agent <subagent_type=> --duration-ms <duration_ms> --tokens <subagent_tokens> --tool-uses <tool_uses>`: the flags copied from the pinned lines, never recomputed, and the three numbers from the notification's `<usage>` block; a failed or empty return is `--verdict failed`. Every return is recorded, whatever its verdict: each design span with its own `executor-route --drafter`, `--critic` or `--judge` lines (`--route design|critic|judge --tier -`, `--agent` its `subagent_type=` line), the mockup span like any slice. (5) **Explore for lookups:** your planning research uses the project `Explore` agent (`subagent_type: Explore`) at the `--explore` form's `model` / `effort` (haiku @ high; `sonnet` under a loopback proxy), upgraded per call — `model: sonnet` or `model: opus` — for a lookup that needs judgment (why, a trade-off, an audit); it locates and summarizes, never decides, and its brief is advisory input to your plan, never a plan (`Plan`-type agents and inline reads stay available). `/executor-route` shows the resolved table and `python3 scripts/workflow.py dispatch-summary` the recorded runs; `executors.toml`'s per-row `[claude.<row>]` overrides are the operator's knob — there are no presets.
