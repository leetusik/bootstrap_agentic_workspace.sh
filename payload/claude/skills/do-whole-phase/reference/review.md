# The review: the orchestrator's side

The review's procedure is the `review-phase` skill, the executor's; this file is only what you do around it.

**Before you dispatch it**, run `python3 scripts/workflow.py dispatch-summary --phase <P>` and compare the spend with `topics/breakdown.md`'s `## Estimate`; past about one and a half times it, set the slice `pending --stop-kind decision --on-words "<what each answer does>"` and STOP (a go-on, with its new figure, goes on `## Decisions`, so it never asks twice). Do the same before a fix pass.

**Plan it** (`executor-route <P>.REVIEW`, the high row) naming: `phase scope <P>`'s output, `topics/walkthrough.md` to run line by line, `next`'s `pr_branch=` lines and the `pathspec=` line(s), and the code reader: dispatched by the review executor itself, or `code reader: n/a (0 product files)`, or `code reader: skipped (operator: "<their words>")` (only the operator's own words skip it, for this round). An explain phase's review is planned from `reference/explain-review.md`.

## On its verdict

- **A would-pass with PR bodies:** open the drafts by the `pr` skill's *Open the drafts* (push each recorded branch, never `--force`; `gh pr create --draft`; `pr-record <P> --branch <b> --url <url>`), with no stop and no word, then read each PR's CI before the gate; a red run becomes a fix before the gate, never after the accept. The `pr-reader` runs only when the operator asks, or for a team repo with PR rules (`executor-route --reader`). An open failure (no `gh`, auth, the network, a refused push) is `pending --stop-kind operator-action --on-words "<what fixing it resumes>"`; a refused draft is never retried as a plain PR: `pending --stop-kind decision` for the operator's `plain` or `waive`. The engine refuses the pass until every recorded branch has its URL or `pr-record <P> --waive --note "why"` ran.
- **A pass on a gated phase:** `accept-gate <P> --open --walkthrough "<the walkthrough as run, opened by the draft URLs and CI>"`, file the deferred jobs it lists (`defer-job`), `check`, commit, report by the stop rules, and STOP. The operator's `accept` clears it (`accept-gate <P> --clear`, theirs or yours on their word). On the resume the `REVIEW` slice is still `in_progress` with `review_verdict: pass`: run the close's step A (`.claude/skills/pr/reference/close.md`: `pr-sync`, the re-read), record the pass **without re-dispatching the review**, then its step B (Ready; a solo repo's merge by its custom after green CI; a team repo's stays the team's). A waived or legacy gate records the pass once the drafts are open; its PR stays a draft until the operator's `close`.
- **Record it:** `python3 scripts/workflow.py review-phase <P> --verdict pass|changes_requested|blocked --reviewer slice-executor --note "..."`, then `check`. A pass marks the phase `done` and closes the `REVIEW` slice (no `slice finish` for it); it never archives.
- **`changes_requested`:** for each `fix now` class, `slice new --phase <P> --slice <P>.F<n> --name "…" --kind fix --risk <low|high>`, `high` when it repairs work the mid row did (work the mid row got wrong never goes back to it), its case list copied into the fix's `plan.md` as the acceptance matrix. File the `note` findings at the pass. **The fix pass runs once**; the review's second dispatch is the closing run.
- **Stop instead of another round.** When the closing run marks `fix did not hold: finding <k>` or `new at the closing run: finding <k>` (or `review-phase` prints `fix_passes=<n>`), cut no further fix: set the `REVIEW` slice `pending --stop-kind decision --on-words "<what each answer does>"` naming the premise the failed fix rested on, and STOP. The answers: one more fix with a simpler rule; accept and defer the rest; or cut scope in `intent.md`. Each buys one fix pass or one closing run.
- **Failures the operator reports at the gate:** `review-phase <P> --verdict changes_requested --note "operator-reported: ..."` (never refused; it resets the gate), fix slices, then the closing run. **After the phase is done** (pass recorded, PR open): never `review-phase`, always `phase reopen <P> --note "team-reported: <what>"` or `"operator-reported: <what>"`, by `.claude/skills/pr/reference/reopen.md`.

**Nothing is left running:** the review stops what the phase started and says so in `result.md`; check its line before you open the gate.
