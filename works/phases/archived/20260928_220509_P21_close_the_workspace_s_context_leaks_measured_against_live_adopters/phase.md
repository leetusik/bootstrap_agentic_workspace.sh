## Decisions

_Durable cross-slice decisions. Replace a superseded line; never stack versions._

- Research-first cut: the fix list was not knowable before measuring, so `DECOMP` created only `S1` + `DECOMP2`. (P21.DECOMP)
- Scope boundary held: machinery and doctrine in **this** repo only; the four adopter repos are read-only evidence (verified clean by S1 and again at the review). (P21.DECOMP, P21.REVIEW)
- Acceptance gate stays **waived** (`required: false`, machinery and doctrine only): no remedy touches an operator-visible running product. (P21.DECOMP, P21.DECOMP2)
- **The doc-rewrite leak is dominant; everything else is a rounding error.** Per-review consolidation is **90-97 %** of the review's read budget; changple5's `backend.md` is v0054 / 420 KB with its last 16 versions averaging **2.7 %** new lines, and one review exceeded a 1 M-token window. Full numbers: S1 §2; the public version is the `## v38` CHANGELOG entry. (P21.S1 §2)
- **The remedy defers *when* consolidation runs, not *what* a doc version is.** Consolidation supersedes wrong lines in place, so a delta format would trade a size problem for a correctness one; sectioning cuts the read to 10-18 % in changple5 but **83-143 %** in the three small-doc repos -- an S5-only secondary, never the substitute. (P21.S1 §2.4, §2.7)
- **Deferral is a generalisation of parallel mode (running since v24), not an invention.** `phase.json` carries a top-level `consolidation` (`pending`/`done`; absent = nothing owed), stamped by a passing review with a non-empty `## Doc impact` list, paid by `docs-consolidated <P>`; `_phase_blockers` holds an owing phase out of archiving, which is what keeps its notes in `active/`. `execution.consolidation` stays readable and is mirrored on write, so `parallel-*` is unchanged. (P21.S1 §11c, P21.S2)
- **Deferral buys two savings beyond the review's critical path:** batching every 5 phases yields **3.3x fewer doc versions** (changple5: 368 -> 111), and re-review rounds stop re-consolidating -- **11 %** of changple5's and **23 %** of Mijual's versions today. (P21.S1 §2.6)
- **Both couplings are handled.** (1) The gate's two writes survive as the review's **narrow named carve-out** -- `## Regression Checklist` (qa), `## Operator Runtime` (operations), that section only, ~13 k tok worst case against 74-734 k saved; a parallel branch review still writes nothing. (2) Staleness is now operator-paced, so the debt is **visible**: S3's one advisory `consolidation_owed=` line in `next` and the same text as a `validate` **warning**, never an error, behind one constant. (P21.S1 §11d, P21.S2, P21.S3)
- **`plan.md` + `result.md` suffice -- do not add a third file.** 9 ad-hoc third files across 1,137 slices (0.8 %); verdict-block-first is **63/63** post-2026-08-29 and 0/1,074 before; the one real `audit.md` is pressure the v36 `research` kind already answers. (P21.S1 §4)
- **Mid-phase compaction is not losing decisions.** 3 tightest notebooks over 49 revisions: every apparent drop was a reword, a spent decision, or already in `result.md`. Key on the decision **id**, never the line text (line-diffing gives 9-18 false drops). (P21.S1 §3.3)
- **Executor validation is a wall-clock cost, not a context leak.** 43 % of slices run a whole suite, but the recorded validation block is a median **1,032 B**: trimming it buys safety loss for no tokens. (P21.S1 §6)
- **The notebook budget works, but its shape is wrong.** Every budget-era phase is under it, but the **byte ceiling binds and the line ceiling never does** (92 % of 16,384 B vs 69 % of 200 lines) and **37 % of the ceiling is incompressible** -- generated `## Slices` (18.9 %) + append-only `## Doc impact` (18.1 %), which deferral makes worse. (P21.S1 §3.2)
- **keep-tests-small needs teeth in exactly one place: changple5** (test:source **0.42** vs 0.11-0.13 in the other three). 40 post-rule files exceed 20 KB, but 218 files / 2.86 MB predate the workspace, so half the sprawl is inherited culture and this is only weakly a *context* leak; the `test:source` ratio is a cleaner lever than a per-file cap. ## Operator Questions

_Questions only the operator can answer. Append only; every entry is routed at the review -- folded into the acceptance walkthrough or filed with `defer-job`. An unrouted entry is a review finding._

- **OQ1 -- how often will you actually run a docs phase?** The remedy makes `docs/current` staleness operator-paced. At every 5 phases the batching win is 3.3x; at every 10 it is 5.9x, but changple5 would then carry ~10 phases of unconsolidated `## Doc impact` notes, and those notes are read by every slice out of a 16 KB notebook. A stated target cadence lets `DECOMP2` size the debt-visibility remedy (R3). (P21.S1)
- **OQ2 -- `CLAUDE.md` + agent files are ~16.3 k tokens on every dispatch and grew 5x in two months. Act, or accept?** Cutting them trades tokens for behaviour, and the contract's completeness is load-bearing, so this is not a measurement call. If "act", `DECOMP2` can cut a compaction slice; if "accept", say so and it stays a recorded number. (P21.S1 §6)
- **OQ3 -- should the notebook budget become bytes-only, and should it be raised?** Lines never bind (69 % occupancy vs 92 % of bytes). Separately, 37 % of the ceiling is content the slice cannot compress, and deferring doc consolidation grows the append-only `## Doc impact` share. Options: raise the byte ceiling, exclude the generated `## Slices` block from the count, or move `## Doc impact` out of the notebook. (P21.S1 §3.2)
- **OQ4 -- changple5's test sprawl is in an adopter repo this phase may not edit.** The measurement says teeth are needed there and only there. Do you want `DECOMP2` to ship a documented procedure / an advisory `validate` warning that changple5 runs itself, or to leave the rule as-is and treat 0.42 as that repo's inherited baseline? (P21.S1 §7)
