- **Order: S1 before S2, deliberately.** S1 lifts the 16 KB notebook squeeze, so S2 -- the notes-heavy slice -- writes its state into a notebook that no longer forces compression. This phase's own evidence (four P21 slices had to compress unrelated content to land) is the argument. (P22.DECOMP)
- **D14 shape (from `intent.md`, not re-decided here).** Every durable doc carries an explicit last-updated marker -- **source commit, date, consolidating phase** -- recorded in `docs/index.json` and surfaced where agents actually read docs (the `workflow.py docs` listing and/or a generated header on `docs/current/*.md`), plus doctrine: a doc whose last update predates the owed `## Doc impact` notes is **stale evidence to check against the notes, never current truth**. (P22.DECOMP)
- **No cadence knob, by operator decision.** Docs phases run only when the operator asks. `CONSOLIDATION_DEBT_MIN_PHASES` stays `1` unless the work turns up a contradiction -- and if it does, `S2` says so rather than tuning it silently. Explicit staleness is what the operator took *instead of* a cadence. (P22.DECOMP)
- **D15 shape.** Replace `PHASE_MD_BUDGET = (200, 16*1024)` with one generous **byte** cap standing in for ~100k tokens (~400 KB of text). The line ceiling **goes**: P21 measured that it never binds (69 % of 200 lines vs 92 % of 16,384 B). Warning-only, never an error -- unchanged. `finish-slice` keeps printing the size (lines *and* bytes are fine to print; only bytes judge). (P22.DECOMP)
- **D16 shape.** Sharpen keep-tests-small to **core-only**: test files exist for very core behavior (logic the product cannot afford to break), never for style/cosmetic/trivial surface -- that is verified live (running it, smoke checks, the real-browser sweep). Tests stay very small. The rule text lives in exactly **one** place in the machinery -- `CLAUDE.md` Hard Rules -- plus `docs/current/qa.md` as durable truth; the two executor agent files do **not** restate it (checked at DECOMP). (P22.DECOMP)
- **D14/D15/D16 are closed by dropping, not promoting, at review-pass time.** Their titles are the *superseded questions* ("state a cadence", "decide the budget's shape", "decide whether the rule grows teeth"), and the operator answered all three differently -- so a promotion would bind a slice to a question that no longer exists, and `promote-deferred` would also create a slice this phase already has. Commands for the orchestrator at the pass: `python3 scripts/workflow.py drop-deferred D14 --reason "resolved by P22"` (same for `D15`, `D16`). Executors never run them. (P22.DECOMP)
- **Workspace version v39, one CHANGELOG section, opened by the first shipping slice.** `WORKSPACE_VERSION` lives at `installer/main.py:38` (currently 38). `S1` bumps it to 39 and opens a single `## v39` section; `S2` appends its bullets to that same section and owns the lead **"Why this release"** bullet (D14 is the headline). Precedent: P21's `S2` opened `## v38` and S3-S5 appended. (P22.DECOMP)
- **D15 landed as a bare byte int.** `PHASE_MD_BUDGET = 400 * 1024` (not a 1-tuple, not a named pair): `phase_md_size()` still returns `(lines, bytes)` and `finish-slice` still prints both, but **only bytes judge** (`(budget 409600 bytes)`), and `validate` warns on bytes alone. Anything later that reads the constant reads an int. (P22.S1)
- **The over-budget smoke fixture is generated, never committed.** Proving the warning still fires needs a >400 KB notebook, so `tests/retrofit_smoke.sh` Test 10 pads its throwaway fixture with `"- filler\n" * 50_000` (~450 KB) in the existing PAD heredoc -- one number, no checked-in blob, and the four v35 probes (warn / exit 0 / heading drift / `finish-slice` print) are otherwise untouched. (P22.S1)
- **D14 landed as one marker plus one shared line.** Every doc version records `commit` (the HEAD sha at write time, best-effort) beside `created_at` and `source`, in **both** `docs/index.json` and the version frontmatter -- which `rebuild_docs` copies verbatim, so the marker reaches `docs/current` for free. `docs` prints that marker under every doc and flags each doc an unconsolidated `## Doc impact` note has outrun as **STALE**; `validate` warns with the same shared `stale_docs=` line. Advisory everywhere, exit codes unchanged. (P22.S2)
- **No sha backfill for pre-v39 entries; they render `unknown (pre-v39)`.** A backfilled `git log -1 -- <path>` sha would mean "the commit that last touched the file" -- a different fact under the same field name -- and backfilling would either make the read-only `docs` listing a writer or spend a migration that gives adopters nothing. The two absences are distinguished honestly: key missing = `unknown (pre-v39)`, key null = `unknown (no git at write time)`. (P22.S2)
- **`stale_docs=` is its own line, not folded into `consolidation_owed=`, and is not gated on `CONSOLIDATION_DEBT_MIN_PHASES`.** The debt line names *phases* and the paying command; the stale line names the *docs* a reader must not trust -- different axes, both needed. The knob tunes how loud a **debt** is (a debt may wait for a batch); staleness is a fact about the doc in the reader's hand and no cadence may quiet it. The knob stays `1`: nothing in the work contradicted it. `next` was deliberately left alone (it already carries the debt line). (P22.S2)
- **Staleness tracks stamped debt, not in-flight notes.** `phases_owing_consolidation()` only sees phases whose review passed (`consolidation: "pending"`), so a phase's own notes flag nothing while it runs -- deliberate, so "owed" means the same thing in `docs`, `validate`, `docs-debt` and the archiving guard. **P22's own four notes start flagging docs only once `P22.REVIEW` passes.** (P22.S2)
- **Acceptance gate: advisory `--waive`.** This phase changes machinery, doctrine and CLI text only -- no operator-visible running product, nothing to walk in a browser. The changed output (`docs` listing, `validate` / `next` warnings) is agent-facing, exactly like P21.S3's `consolidation_owed=` line, and P21 shipped waived. The call is the orchestrator's; the note it should carry: "machinery and doctrine only; no running product surface". (P22.DECOMP)

  confirmed them; `validate` / smoke (158 PASS) / `build.py --check` / `sync-agents --check` all green; the scope
