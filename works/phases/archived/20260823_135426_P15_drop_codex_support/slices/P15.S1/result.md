The new `[codex.*]` rejection sits immediately after the retired-tier check and mirrors its shape:

```
executors.toml line 3: Codex support was removed in workspace v31 — this workspace ships Claude Code only, so drop this section
```

Its regex is `^\[\s*codex\s*\.\s*[^\]]*\]\s*(?:#.*)?$` — deliberately loose on the tier, so
`[codex.low]` also lands here rather than on the retired-tier message (verified below). Because the
retired-tier regex is now `claude`-only, there is no ordering ambiguity between the two.

Two now-placeholder-free continuation strings in those two `raise SystemExit(...)` blocks lost their
`f` prefixes (cosmetic; no behavior change).

## Deviations from `plan.md`

1. **The "zero `codex` hits" grep is not achievable as written**, because plan item 3 requires adding
   a `[codex.*]` rejection message — which necessarily contains the word. The remaining two hits are
   exactly that path (`scripts/workflow.py:152` regex, `:154` message) and nothing else. `AGENTS.md`,
   `.agents`, and `Codex` outside that message: zero hits.
2. **`values` key tuple simplified** — the plan left this to judgment ("only if it stays clearly
   readable"). Done: `(tier, key)`, with `section` now a plain tier string. `executor_config()`'s
   overlay is a two-line loop and no `harness == "claude"` residue remains anywhere.
3. Two cosmetic `f`-prefix removals on literal-only continuation strings (noted above).

Nothing else. `.agents/`, `.codex/`, `AGENTS.md`, `CLAUDE.md`, `installer/**` (except the generated
artifact), `tests/**`, `README*`, and `docs/**` are untouched.
