# Plan — P34.DECOMP (decompose "Boundary-gated compaction: veto mid-process, resume at the slice boundary")

## Context

The operator wants context compaction to stop landing mid-slice (executor returns → validate → *compaction* → commit) and to land at the slice boundary instead (commit → compact → plan the next slice). Claude Code cannot be told to compact by the orchestrator, so P34 builds the **veto** that steers the automatic compaction: a `PreCompact` hook (matcher `auto`) calling an engine command that blocks mid-slice and allows at a clean boundary, with two fail-safes; a `SessionStart` hook (matcher `compact`) that re-injects the pointer and a resume line; a compact-instructions section in `CLAUDE.md`; and a reorder of the two execution skills so their loop invariants survive the 5,000-token skill re-injection cap. Both hooks ship on for everyone through the installer. The operator's confirmed intent, clarifications and the research notes are in `works/phases/active/P34/intent.md` — read it whole before cutting; the notes there (triggers, re-injection, window semantics, fill measurement, sizes) are the design input.

This slice is the decomposition: it cuts the middle slices as bare folders with `new-slice`, records the breakdown, the cross-slice decisions and the per-slice notes in `phase.md`, and writes nothing else. Executor: `slice-executor-high` (by kind). P34 runs on the default stream (no worktree asked).

## The shape to pin (DECOMP settles it; record the final form in `## Decisions`)

The orchestrator recommends the following; the executor verifies it against the code and may adjust, writing any departure as a Decision with its reason:

1. **Two engine commands, no separate hook script.** `compact-gate` (the `PreCompact` command) and `compact-resume` (the `SessionStart` command) live in `scripts/workflow.py` — that is what the installer already embeds, rewrites for the nested layout and the skills already know how to run; a file under `.claude/hooks/` would need a new manifest entry and its own nested rewrite. Both read the hook's JSON from stdin, need only python3 + git, and **fail open**: any internal error → `allow` (print nothing or `{"decision":"allow"}`… the executor pins the exact allow form) with exit 0, never exit 2 by accident. A short `timeout` (≈15 s) on both hook entries.
2. **`compact-gate` decision, in order:** (a) `trigger != "auto"` → allow (manual `/compact` is never blocked; the matcher already says `auto`, the check is belt-and-braces); (b) **fill ceiling**: read the latest assistant `message.usage` from `transcript_path`, fill = `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`; fill ≥ ceiling → allow; (c) **consecutive-block cap**: a counter keyed by `session_id` in an **untracked** location (`scratchpad_dir` from the hook input when present, else the system temp dir — **never** a tracked path, since a dirty tree is itself a block) — count ≥ cap → allow and reset; (d) **boundary**: block iff the stream's current slice (`resolve_current` on this checkout) is `in_progress`, **or** the tree is dirty; else allow and reset the counter. Every block increments the counter. The `reason` names which rule fired (`slice P34.S1 in_progress`, `dirty: 3 files`) so a `/compact` user or the debug log can see why.
   - **"Dirty" excludes the generated works dashboards** (`works/state.json`, `works/index.json`, `works/backlog.md`, `works/deferred.md`): every `next` rewrites their timestamps, so counting them would block at every boundary. Use `git status --porcelain --untracked-files=all` with that exclusion (reuse `_git` / the `_status_product_files` pattern).
   - **Ceiling:** 850k when the latest assistant `message.model` is a 1M-window model (the Claude 5 family), a conservative figure otherwise (e.g. 85% of 200k); overridable by an environment variable (name it in the Decision, e.g. `AGENTIC_COMPACT_CEILING`). **When in doubt, allow** — an unexpected allow only costs the boundary property; a wrong block can fail a request. Unreadable transcript or usage → treat as above the ceiling? No: → skip rule (b) and continue (the cap still bounds it); the executor pins which and says why.
   - **Cap:** a small fixed number of consecutive blocks (the intent says "a cap"; propose 8 — one block per request, so 8 requests ≈ one executor cycle's worth of orchestrator turns), overridable by the same env mechanism.
   - **Statuses:** `in_progress` blocks; `todo`, `ready`, `pending`, `done`, `blocked`, `changes_requested` allow (the phase-level `pending` gate and a `done` phase allow); the executor checks `in_review` (the review slice while the engine runs `review-phase`) and pins it.
3. **`compact-resume`** prints, as facts: the `next` output (pointer, `WAITING ON OPERATOR` if any), then one resume line — *"Context was compacted. Re-read the running skill's `SKILL.md` from disk (`.claude/skills/<name>/SKILL.md` — only its first 5,000 tokens were re-injected), the active slice folder (`plan.md`, `result.md`), and `phase.md`'s `## Now`; executors still running are listed by the harness."* Under 10,000 characters always; `next`'s own rebuild side effect is acceptable (it already runs at every pointer read) — or call the non-writing parts; the executor pins it.
4. **Shipping the hooks.** `.claude/settings.json` gains `hooks.PreCompact` (matcher `auto`, command `python3 "$CLAUDE_PROJECT_DIR/scripts/workflow.py" compact-gate`, timeout) and `hooks.SessionStart` (matcher `compact`, `compact-resume`). Installer: `_merge_settings_json` gains an **additive hooks merge** — for each event and matcher group in the payload, append the handler unless a handler with the same `command` already exists; never remove or reorder an adopter's own hooks; applied on `--update`, retrofit **and** the nested `settings.local.json` present-file path (the absent-file paths already carry the whole payload); `nested_rewrite` already rewrites the command's path. Smoke assertions: fresh install carries both hooks; update/retrofit onto a `settings.json` with a foreign hook keeps it and adds ours exactly once (idempotent on a second update); nested local file gets them; `compact-gate` piped a fabricated `PreCompact` JSON (fake transcript with a `usage` line) in a `cp -R` copy returns block mid-slice / allow at a boundary / allow above the ceiling / allow after the cap / allow on `manual`; `compact-resume` prints the pointer and the resume line.
5. **Texts.** (a) `CLAUDE.md`: a `## Compact Instructions` section (≤ ~450 B) — keep: the operator's literal words and open gates, the running skill and its mode word, dispatched executor task ids with their slice ids, decisions not yet on disk; drop: tool output already in `plan.md`, `result.md` or `phase.md`. The contract must come back **under the 12,288 B cap** (it is 12,588 B today): trim redundancy elsewhere without dropping a rule, and note the new size in `## Doc impact` for `decisions.md`. (b) **Skill reorder** of `do-whole-phase` and `do-next-slice`: move, not duplicate — the loop invariants (pending/`needs_operator`/`blocked` halts; background dispatch, one executor at a time, no repo writes or state moves while it runs; the dispatch sequence `executor-route` → `## Dispatch` → Agent call → `record-dispatch`; `finish-slice` → `validate` → commit with the recorded attribution) plus a **resume line** (after compaction: re-read this file from disk, the active slice folder, `## Now`) into the first **≤ 16 KB** of each file (5,000 tokens ≈ 17–20 KB at 3.5–4 chars/token; 16 KB leaves headroom), the mode words (`gate`, `plan only`), co-work windows, idle-window prep, worktree integration and the review tail after. Every sentence survives (P32's dispatch protocol and P33's archive lines included); `wc -c` and the byte offset of the last invariant are reported in `result.md`. (c) **Doc impact notes** for `operations.md` (hooks shipped, `compact-gate` rules and fail-safes, `compact-resume`, the installer's hooks merge, and the **recommended `autoCompactWindow` ≈ 300k** — "the earliest allowed point" once the veto exists — set by the operator with `/autocompact 300k`, never by the workspace), `architecture.md` (two new engine commands, settings carry hooks), `decisions.md` (veto over orchestrator-driven compaction; fail-open; the dirty-tree definition), `qa.md` (smoke count, checklist lines).
