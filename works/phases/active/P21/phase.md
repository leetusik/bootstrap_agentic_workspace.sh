# Phase P21: close the workspace's context leaks, measured against live adopters

_Intent: see [intent.md](intent.md)._

## Objective

Measure where the workspace actually spends context across four live adopting repos (changple5 v36, changple_web v35, Mijual v36, arb_upbit_1 v35 -- ~1,140 slices, 83 archived phases between three of them), then close only the leaks the measurement justifies. Confirmed leak with an operator-proposed remedy to research first: per-review durable-doc consolidation rewrites whole docs that only grow (changple5 backend.md at v0054, 420 KB, rewritten by every review) -- research retiring doc-new-version from the review slice in favour of dedicated operator-created docs phases, and what a review still records if so. Open questions: whether the 16 KB phase.md budget is right (post-v35 notebooks ride within bytes of the ceiling -- is mid-phase compaction losing decisions under that pressure?); whether plan.md + result.md suffice as the orchestrator's post-slice record; what the review may read instead of every result.md; executor validation cost; where keep-tests-small needs teeth (changple5: 494 test files / 6.3 MB; the other three comply). Two suspects retracted by measurement: archiving works (rotate-backlog; 56/20/7 archived) and the notebook budget is respected since v35. DECOMP cuts a research slice first -- the fix list is not knowable before the measurement -- and DECOMP2 cuts the remedies from findings. Machinery and doctrine only: adopter repos are read as evidence and receive a documented procedure, never edits from here.

## Decisions

_Durable cross-slice decisions. Replace a superseded line; never stack versions._

- Research-first cut: the fix list was not knowable before measuring, so `DECOMP` created only `S1` + `DECOMP2`; S1 measured, `DECOMP2` cut the remedies. (P21.DECOMP, P21.S1, P21.DECOMP2)
- Scope boundary held: machinery and doctrine in **this** repo only; the four adopter repos are read-only evidence (S1 verified them clean afterwards) and anything they need ships as a procedure they run. (P21.DECOMP)
- Acceptance gate stays **waived** (`required: false`, "machinery and doctrine only"): no cut remedy touches an operator-visible running product. (P21.DECOMP, P21.DECOMP2)
- **The doc-rewrite leak is dominant; everything else is a rounding error.** Per-review consolidation is **90-97 %** of the review's read budget; changple5's `backend.md` is v0054 / 420 KB with its last 16 versions averaging **2.7 %** new lines, and one review exceeded a 1 M-token window. Full numbers: S1 §2; the public version is the `## v38` CHANGELOG entry. (P21.S1 §2)
- **The remedy defers *when* consolidation runs, not *what* a doc version is.** Consolidation supersedes wrong lines in place, so a delta format would trade a size problem for a correctness one; sectioning cuts the read to 10-18 % in changple5 but **83-143 %** in the three small-doc repos -- an S5-only secondary, never the substitute. (P21.S1 §2.4, §2.7)
- **Deferral landed as a generalisation of parallel mode (which has run it since v24), not an invention.** `phase.json` carries a top-level `consolidation` (`pending`/`done`; absent = nothing owed), stamped by a passing review with a non-empty `## Doc impact` list and paid by `docs-consolidated <P>`; `_phase_blockers` holds an owing phase out of archiving, which is what keeps its notes in `active/`. `execution.consolidation` stays readable as the legacy fallback and is mirrored on write, so `parallel-*` is unchanged. (P21.S1 §11c, P21.S2)
- **Deferral buys two savings beyond the review's critical path:** batching every 5 phases yields **3.3x fewer doc versions** (changple5: 368 -> 111), and re-review rounds stop re-consolidating -- **11 %** of changple5's and **23 %** of Mijual's versions today. (P21.S1 §2.6)
- **Both couplings are handled.** (1) The gate's two writes survive as the review's **narrow named carve-out** -- `## Regression Checklist` (qa) and `## Operator Runtime` (operations), each via `doc-new-version` on that section only, ~13 k tok worst case against 74-734 k saved; a parallel branch review still writes nothing. (2) `docs/current` staleness is now operator-paced, so the debt must be **visible**: `S3` landed one advisory `consolidation_owed=` line in `next` plus the same text as a `validate` **warning** (never an error), behind one constant. (P21.S1 §11d, P21.S2, P21.S3)
- **`plan.md` + `result.md` suffice -- do not add a third file.** 9 ad-hoc third files across 1,137 slices (0.8 %); verdict-block-first is **63/63** post-2026-08-29 and 0/1,074 before; the one real `audit.md` is pressure the v36 `research` kind already answers. (P21.S1 §4)
- **Mid-phase compaction is not losing decisions.** 3 tightest notebooks over 49 revisions: every apparent drop was a reword, a spent decision, or already in `result.md`. Key on the decision **id**, never the line text (line-diffing gives 9-18 false drops). (P21.S1 §3.3)
- **Executor validation is a wall-clock cost, not a context leak.** 43 % of slices run a whole suite, but the recorded validation block is a median **1,032 B**: trimming it buys safety loss for no tokens. (P21.S1 §6)
- **The notebook budget works, but its shape is wrong.** Every budget-era phase is under it, but the **byte ceiling binds and the line ceiling never does** (92 % of 16,384 B vs 69 % of 200 lines) and **37 % of the ceiling is incompressible** -- generated `## Slices` (18.9 %) + append-only `## Doc impact` (18.1 %), which deferral makes worse. (P21.S1 §3.2)
- **keep-tests-small needs teeth in exactly one place: changple5** (test:source **0.42** vs 0.11-0.13 in the other three). 40 post-rule files exceed 20 KB, but 218 files / 2.86 MB predate the workspace, so half the sprawl is inherited culture and this is only weakly a *context* leak; the `test:source` ratio is a cleaner lever than a per-file cap. (P21.S1 §7)
- **A leak the intent did not name: the contract itself.** `CLAUDE.md` + the executor agent file are **~16.3 k tokens on every dispatch**, up **5x in two months** (21,711 B -> 65,233 B at v37). Same shape as the doc leak, but the contract's completeness is load-bearing, so acting is an operator call (OQ2) -- no slice cut. (P21.S1 §6, P21.DECOMP2)
- **This repo eats it immediately: `P21.REVIEW` follows the new rule** -- verify the `## Doc impact` list, create **no** doc versions (waived gate = not even the carve-out), and the engine stamps `P21` `consolidation: pending`, holding it in `active/` until a docs phase records `docs-consolidated P21`. Workspace **v38** (`installer/main.py`), one open `## v38` CHANGELOG section. (P21.S2)
- **The docs phase has an entry point; default cut is one slice per doc.** `docs-debt` (read-only) prints the worklist -- owing phases, their notes, the docs named, the paying command -- and `create-phase`'s *docs-phase route* proposes it as the scope through the **unchanged** step-3 gate. Per doc because `doc-new-version` is; the debt stays per phase. A docs phase leaves no notes, so it cannot feed itself. (P21.S4)
- **R5 shipped as visibility, not surgery.** One constant (`DOC_SECTION_WARN_BYTES` = 10 KB, S1 §2.8's own cut line: 10 % of adopter H2 sections are over it, worst 112,619 B) and one shared line -- `validate` warns, `doc-new-version` repeats it beside `edit_path`, where a split can actually land. Advisory at both sites, exit codes unchanged; splitting stays per-doc judgment in a docs phase because sectioning **hurts** small-doc repos (S1 §2.4). No auto-split, no config, no CLAUDE.md paragraph. (P21.S5)
- **The cut: four remedy slices, R1+R2 merged into one.** `S2` = R1 (defer consolidation) **plus R2** (the review's narrow named write to `## Regression Checklist` / `## Operator Runtime`): R2's file set is a **subset** of R1's, so merging satisfies "R2 with or before R1" structurally instead of by ordering discipline, and avoids an incoherent intermediate in a self-hosting repo. `S3`/`S4` follow on S2's state shape; `S5` is independent. All four `high` -- each edits `scripts/workflow.py`, `CLAUDE.md` or `.claude/*` and triggers the installer rebuild. (P21.DECOMP2)

## Operator Questions

_Questions only the operator can answer. Append only; every entry is routed at the review -- folded into the acceptance walkthrough or filed with `defer-job`. An unrouted entry is a review finding._

- **OQ1 -- how often will you actually run a docs phase?** The remedy makes `docs/current` staleness operator-paced. At every 5 phases the batching win is 3.3x; at every 10 it is 5.9x, but changple5 would then carry ~10 phases of unconsolidated `## Doc impact` notes, and those notes are read by every slice out of a 16 KB notebook. A stated target cadence lets `DECOMP2` size the debt-visibility remedy (R3). (P21.S1)
- **OQ2 -- `CLAUDE.md` + agent files are ~16.3 k tokens on every dispatch and grew 5x in two months. Act, or accept?** Cutting them trades tokens for behaviour, and the contract's completeness is load-bearing, so this is not a measurement call. If "act", `DECOMP2` can cut a compaction slice; if "accept", say so and it stays a recorded number. (P21.S1 §6)
- **OQ3 -- should the notebook budget become bytes-only, and should it be raised?** Lines never bind (69 % occupancy vs 92 % of bytes). Separately, 37 % of the ceiling is content the slice cannot compress, and deferring doc consolidation grows the append-only `## Doc impact` share. Options: raise the byte ceiling, exclude the generated `## Slices` block from the count, or move `## Doc impact` out of the notebook. (P21.S1 §3.2)
- **OQ4 -- changple5's test sprawl is in an adopter repo this phase may not edit.** The measurement says teeth are needed there and only there. Do you want `DECOMP2` to ship a documented procedure / an advisory `validate` warning that changple5 runs itself, or to leave the rule as-is and treat 0.42 as that repo's inherited baseline? (P21.S1 §7)
