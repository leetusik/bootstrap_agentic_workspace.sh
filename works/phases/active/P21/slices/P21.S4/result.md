## 1. What landed, and why in this shape

Before this slice the rule existed everywhere ("durable docs are versioned in a docs phase the
operator creates") and the *how* existed nowhere: an operator saying "run a docs phase" — or
clearing the `consolidation_owed=` line S3 added — had to re-derive the scope by hand out of several
phase notebooks. Three pieces close that, in the order the operator meets them:

1. **`docs-debt` (new, read-only).** The worklist. For every phase `phases_owing_consolidation()`
   returns it prints the phase, its `## Doc impact` notes verbatim, and the paying command from
   `consolidation_command()` — then a **per-doc rollup** (which docs, how many notes, from which
   phases), then the per-note `doc-new-version → rebuild-docs` sequence. It reads the debt only
   through the S3/S2 helpers, so the legacy `execution.consolidation` shape needs no special case
   and a merged parallel phase is named with `parallel-consolidated`, never with a command the
   engine would refuse. It writes nothing at all — no `rebuild`, no index touch.
2. **The `create-phase` docs-phase route.** A step-2 pointer ("the scope is already written down —
   run `docs-debt`") plus a `## The docs-phase route` section placed **after step 5**, so the
   numbered procedure stays contiguous. The route is explicitly a specialization, not a bypass:
   same refine → clarify → **confirm at step 3** → `new-phase` → STOP. No new gate, no gate moved.
3. **Discoverability.** `CLAUDE.md`'s durable-docs hard rule now ends with the route in one clause,
   and the command list names `docs-debt` on the existing `docs-consolidated` line. The file's line
   count is unchanged (120), which was the OQ2 constraint the plan set.

Two things the route states so the phase cannot feed itself or drift: **the default cut is one slice
per doc** (`doc-new-version` is per doc, and one doc typically collects notes from several phases —
per-doc keeps each doc to a single new version), and **a docs phase leaves no `## Doc impact` notes
of its own**, so its own review stamps no new debt; its gate is normally waived.

## 2. Design notes worth keeping

- **Why a per-doc rollup and not just per-phase blocks.** The docs phase's `DECOMP` cuts per doc but
  the *debt* is per phase (`docs-consolidated <P>` clears a phase, and that is what unblocks
  archiving). Printing both means neither the intake nor the `DECOMP` has to invert the other's view.
- **`(unassigned)` instead of guessing.** `doc_impact_docs()` matches a note against the known
  `DOC_TYPES` only (`<doc>.md`, several per note allowed — `operations.md: …; qa.md: …` counts for
  both). A note naming no known doc is listed under `(unassigned)`, excluded from the `docs=` header
  and the doc count, and handed to the operator to read. Nothing routes on the guess.
- **No `--phase` filter, no config.** The command is a worklist, not a query language; the docs
  phase's own slices work from their `plan.md`, not from re-running this with flags.
- **A phase owing docs with an empty notes list** (the notebook was compressed after the debt was
  stamped) prints an explicit line pointing at git history rather than an empty block.
