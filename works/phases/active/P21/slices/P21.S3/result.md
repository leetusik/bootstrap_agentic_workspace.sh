## 1. What landed

S2 made the debt *exist* and deliberately left `next` / `validate` untouched. This slice makes it
*visible*, because deferral traded review cost for operator-paced `docs/current` staleness and the
one outcome that trade may not have is **silent** staleness (S1 §11d, coupling 2).

Everything is in `scripts/workflow.py`:

| piece | what it is |
|---|---|
| `CONSOLIDATION_DEBT_MIN_PHASES = 1` | the **only** "how loud" knob, and it is a module constant, not config. `1` = always show the line whenever anything owes. An OQ1 cadence answer can raise it later without re-cutting anything; nothing else in the engine branches on how much is owed. |
| `consolidation_command(phase)` | the command that pays **one** phase's debt (`parallel-consolidated` for a parallel phase, `docs-consolidated` otherwise). New, but not new behaviour — `_phase_blockers` had this expression inline and now calls the helper, so the archiving guard, `next` and `validate` can never name a command the engine would refuse. |
| `consolidation_debt_line(phases)` | builds the single advisory line, or `""`. Shared by `next` and `validate` so the two cannot word it differently. Reads only through `phases_owing_consolidation()` / `phase_consolidation()` / `phase_execution()`, so it accepts either phase records or `works/index.json` entries and both live state shapes. |
| `cmd_next` | prints the line right after the stream lines and **before every `return` below it**, so no path hides it — including the `waiting_on_operator` halt, which is exactly when an operator is most likely to be reading. Selects nothing; changes nothing else. |
| `validate` | appends the same text to `warnings`. **Warning, never an error** (exit stays 0) — the debt is expected operator-paced state, so it must not fail CI or block the loop. |
| `parallel_merge_finish` | one message only: its empty case now says `no merged phase awaits doc consolidation (merged parallel phases only -- next/validate name every phase that owes)`. Its listing is scoped to *merged parallel* phases, so without that clause it flatly contradicts a `next` line naming default-stream phases. |

The line, verbatim, from the scratch copy with one phase of each shape owing:

```
consolidation_owed=P22, P23 (2 phases owe durable-doc consolidation; docs/current trails the code until a docs phase runs doc-new-version over each '## Doc impact' list, then: docs-consolidated <P>) -- P23 came from a parallel branch: pay those with parallel-consolidated, on the default stream
```

`key=value`, greppable on `consolidation_owed=`, ids first and clean (no per-id annotation), the
parallel qualifier in the trailing clause. `validate` prints the identical text behind its
`warning: ` prefix. With one owing phase it reads `1 phase owes`; with none, nothing is printed at
all — the live repo's `next` and `validate` are byte-identical to before this slice.

## 6. Notes for whoever reads this next

- **Where the line is printed matters more than what it says.** Putting it before `cmd_next`'s early
  returns is deliberate: the `waiting_on_operator` branch returns without ever reaching the pointer
  lines, and that branch is precisely the moment an operator is reading the output.
- **`index.json` entries are a legal input to the helper.** `rebuild_index_and_state` copies both
  `consolidation` and `execution` onto each active-phase entry, so `cmd_next` reuses the index it
  already read instead of re-walking the phase tree. If that projection ever drops a field, the
  helper degrades to "no debt" silently — a second reason it must never become the only surface (the
  archiving guard reads `phase.json` directly and stays the hard stop).
- **Considered and rejected: annotating each id inline** (`P23(parallel-consolidated)`). It keeps the
  line shorter but makes `consolidation_owed=` un-splittable by a downstream reader; the trailing
  clause costs a few bytes and keeps the value a plain comma-separated id list.
- **Considered and rejected: a debt line in `works/backlog.md`.** The dashboards are regenerated
  state and the rule is that they stay lean (ids, statuses, pointers); the debt is already per-phase
  in `works/index.json`, and `next` / `validate` are the two surfaces an agent actually reads.
