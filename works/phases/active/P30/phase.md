# Phase P30: Rotate-backlog creates the docs phase by default

_Intent: see [intent.md](intent.md)._

## Objective

An opt-out word (e.g. /rotate-backlog archive-only) keeps today's archive-and-report behavior.

- **The cut (P30.DECOMP):** `P30.S1` engine → `P30.S2` skills, texts and release v51 (`depends_on` S1) → `P30.REVIEW`. Both are `implementation / low` (mid tier): the approach is pinned below, the one schema addition is an optional `phase.json` key with no migration, archiving logic is untouched, and no high trigger applies. No research slice is needed: every open point is pinned. Acceptance gate: **required** (`/rotate-backlog`'s default behaviour is an operator-run surface); the orchestrator runs `accept-gate P30 --require`.
- **D1 `new-phase --consolidates P26,P27,…` (S1):** writes `"consolidates": ["P26", …]` into the new `phase.json`; the key is absent without the flag (old phases need no migration). It refuses, writing nothing, when a named id is not an active phase owing consolidation. It is the **only** docs-phase marker: nothing reads phase names or intent text to detect a docs phase. `validate` accepts the key and errors on a malformed one (not a non-empty list of `P<N>` ids). **Final (S1):** the flag tolerates spaces and dedupes in order; a refusal (`--consolidates refused, nothing was written: P30 (owes no doc consolidation: ...); P99 (not an active phase)`) runs before any write; a successful run adds a `consolidates=P26, P27 (docs phase: ...)` line after `created phase`. `phase_consolidates` and `consolidation_cover` are the shared readers.
- **D2 `rotate-backlog [--archive-only]` (S1):** archiving and its output stay byte-for-byte as today. After them, unless `--archive-only`, it prints a read-only **proposal block**:
  - *Debt-only phases* are the remaining active phases whose only `_phase_blockers` reason is consolidation: every slice done, review `pass`, `consolidation: pending`. `_phase_blockers` is restructured minimally (e.g. a reason kind) so this is a check, not string matching. `archive-phase`, `archive-all` and rotate keep identical refusal text. A parallel-mode phase not yet merged is never debt-only.
  - *Already covered:* an active, **not-done** phase whose `consolidates` intersects the debt-only set covers those phases. It prints `docs_phase_covered=<PX> (pays P26, P27)` and proposes nothing for them.
  - *Proposal* for the uncovered remainder, as key=value lines: `docs_phase_proposal=P26, P27, P28, P29`; `phase=P<next>`, one above the highest number across active **and** archived phases (folder names carry `_P<N>_`; `archive_manifest.json` has `phase_id`); `name=Consolidate the doc impact of P26–P29`; `objective=consolidate the '## Doc impact' notes from P26, P27, P28, P29 into new versions of <docs from stale_docs>`; the exact `{WORKFLOW_CMD} new-phase --phase … --name "…" --objective "…" --consolidates P26,P27,P28,P29`; a pointer to `{WORKFLOW_CMD} docs-debt` for the scope; and a closing line saying the proposal wrote nothing and the create-phase confirmation gate applies.
  - *Nothing to propose* (no debt-only phase): the single line `docs_phase=none`.
  - *Other blockers* stay in today's `left N phase(s) active` line and are never proposed.
  - The `no done phases to rotate` early return still prints the block, since the debt-only phases are exactly what remains.
  - **Final (S1), the printed keys S2 writes from:** `docs_phase=none` | `docs_phase_covered=<PX> (pays P26, P27)` (one line per covering phase) | `docs_phase_proposal=P26, P27, P28, P29`, `phase=P31`, `name=…`, `objective=…`, `create: <WORKFLOW_CMD> new-phase --phase P31 --name "…" --objective "…" --consolidates P26,P27,P28,P29`, `scope: <WORKFLOW_CMD> docs-debt`, `proposal only: nothing was created -- confirm the name and objective with the operator first (create-phase's docs-phase route)`. Covered lines come first, then the proposal for the uncovered rest (so one run can print both). Early returns: **both** early returns call the same `_print_docs_phase_proposal()`, so `no active phases to rotate` prints `docs_phase=none`; `--archive-only` skips it on every path and leaves every older line byte-for-byte. Every other rotate also prints `docs_phase=none` when nothing is debt-only (a new additive line). Name rule: `of P26`, `P26–P29` (en dash) for consecutive numbers, else `P26, P28, P29`; docs from `stale_docs` of the uncovered phases, else `the docs their notes name`. The `create:` line double-quotes name and objective (readable, `'## Doc impact'` stays literal) and falls back to `shlex.quote` only for text a double-quoted word would expand.
- **D3 `docs-debt` (S1):** adds one line per owing phase a live docs phase already covers (`  paid by: P31 (in progress)`). That is its only change, and it stays read-only.
- **D4 Not touched (S1):** the archive gate (whether `_phase_blockers` blocks or not), the archive manifest, and the behaviour of `archive-all` and `archive-phase`. Rotate never runs `new-phase` itself; the skill does, after the operator's yes.
- **D5 Tests, core only (S1):** one small smoke block beside the `docs-debt` fixture with three probes. (a) A debt-only phase makes rotate print `docs_phase_proposal=` and the exact `new-phase … --consolidates` command, and stays active. (b) After `new-phase --consolidates` for it, rotate prints `docs_phase_covered=` and no proposal; `new-phase --consolidates` naming a phase that owes nothing refuses. (c) `--archive-only` prints no proposal block. The suite runs once, alone in its own foreground Bash call, and the count is reported against the baseline.
- **D6 Doc impact (S1 and S2 each):** one-line notes for operations (the archive/rotate runbook, the docs-phase route entry), architecture (the `consolidates` key, the rotate proposal) and decisions (why an explicit key rather than name or intent detection; why rotate proposes rather than creates, which keeps the confirmation gate). No `doc-new-version` in this phase.
- **D7 The rotate-backlog skill flow (S2):**
  - It runs `rotate-backlog`, or `rotate-backlog --archive-only` when the args carry `archive-only`, and relays what was archived.
  - On a proposal block it presents the name, the objective and the docs scope (`docs-debt`), and asks **once**. The operator may edit the name or objective, or narrow the phase list; a phase left out keeps owing.
  - On the yes it runs the printed `new-phase … --consolidates …` and fills `intent.md` exactly as create-phase's docs-phase route says: the verbatim words, the confirmed intent with the `docs-debt` scope, and the DECOMP cut (one `--kind docs` slice per doc, `docs-consolidated <P>` per covered phase, gate waived). Then it STOPs and never decomposes.
  - With no proposal, or only `docs_phase_covered`, it reports and stops.
  - Frontmatter: it keeps `disable-model-invocation: true`, and `allowed-tools` gains `Read`, `Edit` and `Write` for `intent.md`, so the flow never asks permission for its own steps. The docs phase runs on the default stream; the skill never mentions worktrees.
  - **Final (S2):** the skill is a six-step procedure (run → relay → read the ending → propose and ask once → on the yes run `create:` and fill `intent.md` per create-phase's route, which stays the source of truth → STOP). It adds `argument-hint: "[archive-only]"` (as `executor-mode` does), quotes its description, and it never says "worktree" (its Rules bullet says the docs phase stays on the default stream and any parallel-run hint from `new-phase` is relayed, not acted on).
- **D8 create-phase docs-phase route (S2):** it passes `--consolidates <the confirmed phases>` to `new-phase`, and it names `/rotate-backlog` as the default entry point that proposes this route.
- **D9 archive-phase SKILL.md (S2):** at ~L23 and ~L32, rotate "leaves it active **and proposes the docs phase that pays it**".
- **D10 Release (S2):** CHANGELOG `## v51` lists the new default, `--archive-only`, `new-phase --consolidates` and the `docs-debt` "paid by" line, with the migration note "none required; old phases have no key". `WORKSPACE_VERSION = 51`. `python3 installer/build.py` is run with `--check` passing, in the same change. **Final (S2):** `WORKSPACE_VERSION` lives in `installer/main.py` (not `scripts/workflow.py`); the smoke test pins no literal version (a three-way equality of installer, top changelog heading and fresh marker), so the bump needed no test edit.
