- **(from P23.DECOMP, for P23.S1) Research agenda.** Findings only, no machinery.
  1. Split the contract into rule units: each Hard Rules bullet, each Driving paragraph, each item in the other sections. Per unit record line, bytes, one-line gist, readers (main thread outside any skill / main thread inside skill X / executor on slice kind Y), and where it is already carried (skill or executor body, verbatim or equivalent, `file:line`).
  2. Give each unit one disposition: **STAY** (always-on main-thread routing, or a prohibition or gate core); **CUT** (derived from code — `workflow.py --help`, engine refusals — or already carried everywhere every reader gets it); **MOVE** (some reader lacks it; name the destination); **SPLIT** (the never-core stays, the procedure moves). Two destination tests: (a) a skill body loads only when that skill runs, and 15 of the 17 skills (`disable-model-invocation: true`) run only on an explicit slash command, so a rule may move into a skill only if it matters solely while that skill runs; (b) anything an executor needs goes to the executor bodies or stays in the contract, never into a skill, because executors can't invoke skills.
  3. List every never-rule, confirmation gate and operator-only command, and show each survives in the target. Intent step 4's list is the floor.
  4. Build the pin map: every smoke assertion that reads the contract, where its phrase lives after the cut, and whether that destination's pin list already asserts it.
  5. Check each inbound reference (listed in the next note): still valid, or needs re-pointing?
  6. Write a target outline: sections, the rule stubs each keeps (named, not drafted — prose is the editorial slice's job), and a byte budget per section totalling ≤ 12,288 B. If unreachable, give the honest floor and the reason.
  7. Note drift: every place the contract and a skill or executor body state a rule differently, and which statement should win. Findings, not fixes.
  8. Recommend a cut for DECOMP2: slice count, what each covers, risk and order.
  9. Record baselines: `wc -c` of the contract, both executor files and every destination skill, plus the current smoke PASS count from one run.
