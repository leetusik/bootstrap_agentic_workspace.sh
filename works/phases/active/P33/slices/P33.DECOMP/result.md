## Findings that shaped the Decisions

- **The live docs phase must be keyed directly.** `_print_docs_phase_proposal` starts from debt-only phases. A docs phase that has run `docs-consolidated` for every phase it covers, but has not passed its own review (for example a `needs_operator` stop at the review), therefore prints `docs_phase=none` today. Under the new chain that would take the `archive` branch and strand the docs phase unfinished. So `resume` keys on "non-done default-stream phase with a non-empty `consolidates`".
- **A legacy docs phase sorts behind planned work.** `new-phase` defaults to `max(order) + 1`, and no engine command changes a phase's order. A docs phase created by v51–v53 rotate would therefore sit behind P32/P34, and `do-whole-phase` (which runs `next`'s current phase) would run the wrong phase on `resume`. Hence the order re-assert on `resume`.
- **Termination.** A docs phase's review stamps debt only when its own `## Doc impact` has notes. `create-phase`'s route says a docs phase leaves none, but that is a convention. The skill's "one docs phase per invocation" stop keeps the chain finite whatever a docs phase leaves.
- **Archiving vs. mid-flight.** Today's rotate archives regardless of other phases' state, and intent item 5 says to archive right away when nothing owes. Archiving whole done phases interleaves with no slice, so the mid-flight check guards only the two docs branches.
- **Mid-flight statuses.** The intent names the boundary as `todo`/`ready`/`done` and the mid-flight examples as `in_progress`/`pending`; `in_review`, `blocked` and `changes_requested` fall between them. I chose the conservative reading (they stop the run) and filed it as an operator question.
- **The contract's decomposition carve-out** says DECOMP plans at the gate unless `auto` is explicit. The embedded docs-phase run must therefore name the `/rotate-backlog` invocation as that explicit `auto` (S2 note).
- **`CLAUDE.md` *Making a phase ≠ executing it*** (l.19) also moves: the one invocation creates and runs the docs phase. The intent listed this line; the plan's item 4 did not. It is in S2's note.
- **Version collision:** `works/phases/active/P34/intent.md` l.35 also says "Ships as workspace v54 (P32 ships v53)". This is filed as an operator question with a proposed rule: whichever lands on `main` second renumbers.
- **Smoke gotcha:** the v51 assertion's regex ends `--consolidates P2$`, so S1 must place `--order` before `--consolidates` or update the regex.
- **Not to probe in this checkout:** here `current_stream` is P33's branch, and even a no-op `rotate-backlog` calls `rebuild_index_and_state()`, which rewrites the generated `works/` files.
- **Docs that describe today's behaviour** (for S1/S2's `## Doc impact` notes): `operations.md` ~l.173, ~l.830, ~l.1154–1196; `architecture.md` ~l.31, ~l.400; `decisions.md` v0043, whose rejected alternative "have rotate create the phase itself" this phase now takes on the operator's word.
