# Phase P33: One-shot /rotate-backlog: consolidate the doc debt, then archive

_Intent: see [intent.md](intent.md)._

## Objective

Rework /rotate-backlog so one invocation does the whole clean-up: check docs-debt first and archive nothing up front; when any phase owes consolidation, create the docs phase through create-phase's docs-phase route (the invocation is the operator's yes for the engine-drafted name, objective and docs-debt scope; the proposal is still printed) and run it end to end through do-whole-phase in auto on the default stream (gate as the opt-in word), then archive every done phase, the docs phase included; when nothing owes, archive the done phases right away. The docs phase jumps the queue ahead of planned work when every other slice on the stream is at a boundary, and /rotate-backlog stops and reports when a slice is mid-flight (in_progress or pending). A stop (pending, blocked, needs_operator, a failed review) ends the run and the next /rotate-backlog resumes from the live docs phase; archive-only keeps the archive-and-report path. Ships as workspace v54 (P32 ships v53).

## Decisions

_Durable cross-slice decisions. Replace a superseded line; never stack versions._

- **Cut (P33.DECOMP): two middle slices, not three.** `P33.S1` engine (`implementation / high`, trigger **core invariant**: it moves the archive sweep's preconditions — when phase folders leave `active/` — writes a phase's `order` on resume, and sets the docs phase's position in stream selection) and `P33.S2` skills, contract and the v54 release (`implementation / low`: the texts are pinned below). The plan's S2 and S3 are merged: every machinery edit already rebuilds the installer with `--check` in its own commit, so a standalone release slice would add only the version line and the CHANGELOG entry, plus a second full smoke run; P30 shipped the same subject the same way. No research slice (the open questions were settled by reading the engine and a throwaway probe), no design slice (nothing visual).
- **Engine: `rotate-backlog` (default) is the one resumable step, and its first stdout line is `rotate=<branch>`**, chosen in this precedence: (1) `rotate=refused` on a parallel stream (`current_stream` non-None), writing nothing; (2) `rotate=archive` when nothing owes (no debt-only phase per `_debt_only`, and no live docs phase): today's archive sweep (whole phases, no `--force`) and its report, ending in `docs_phase=none`; (3) `rotate=stop_midflight midflight=<id:status, …>`, archiving nothing; (4) `rotate=resume docs_phase=<P>`, archiving nothing and keeping today's `docs_phase_covered=` lines; (5) `rotate=create` plus today's proposal block, with the `create:` line carrying `--order <jump>`, archiving nothing. **`--archive-only` is unchanged** (today's output, no `rotate=` line, no docs line). `archive-all`, `archive-phase`, the manifest and `_phase_blockers` are untouched. S1 replaces this line with the exact printed lines and exit codes when it lands.
- **Departure from the plan's precedence: `archive` comes before the mid-flight check.** The stop exists so that the docs phase never interleaves with a running slice. Archiving whole done phases interleaves with nothing, and intent item 5 says "when nothing owes, archive the done phases right away" (today's rotate archives regardless of other phases' state). So the mid-flight check guards only `resume` and `create`.
- **Live docs phase** = a non-`done` default-stream phase with a non-empty `consolidates` (`phase_consolidates`), keyed directly rather than through debt-only → `consolidation_cover`. That way a docs phase that has already paid every phase it covers, but has not passed its review yet, still resumes (today's proposal prints `docs_phase=none` there). With several live docs phases, `resume` names the first by order. `resume` beats `create`: uncovered debt waits until the live docs phase is done.
- **Mid-flight** = on the default stream (`stream_phases(phases, None)`), any slice whose status is not `todo`, `ready` or `done`, or any phase whose status is `pending`, `blocked` or `in_review`. Every live docs phase and its slices are excluded, because resuming it is exactly what the run does (its own stops then end the run). Parallel streams are never counted. Reason: the confirmed intent names the boundary positively (`todo`, `ready`, `done`), so `in_review`, `blocked` and `changes_requested` stop the run too. A false stop costs one re-run; a false jump interleaves. This edge is routed as an operator question.
- **The queue jump is an order, not a new state.** The `create:` line's `--order` is `min(order of every non-done default-stream phase) - 1` (omitted when there is none); `0` and negative orders round-trip. `resume` re-asserts the same rule on the live docs phase when it does not already sort first (one `order` write in `phase.json`, printed and logged as an event), so a docs phase created under v51–v53 (default order `max + 1`, behind planned work) also resumes correctly. `next`, `resolve_current`, `stream_phases` and `validate` are unchanged. Verified on a throwaway copy: `new-phase --order 0.5` (and `0`, `-1`) round-trips through `rebuild`, `next` selects it ahead of an order-1 phase, and `validate` passes with two `in_progress` phases on one stream.
- **The skill runs the chain; the engine prints the decisions (S2).** `/rotate-backlog` runs `rotate-backlog` and branches on the first line. `refused` / `stop_midflight`: relay and STOP. `archive`: relay, commit the sweep (`chore(works): archive … with rotate-backlog`) and report. `create`: show the proposal, run the `create:` line **as is** (the invocation is the yes, so there is no pause and no narrowing), fill `intent.md` per `create-phase`'s docs-phase route (origin `operator`, the invocation verbatim, the `docs-debt` scope, the per-doc cut), commit, then continue as `resume`. `resume`: commit any order write, then run the docs phase end to end per `do-whole-phase` in **`auto`**. The `/rotate-backlog` invocation is the explicit `auto` that the contract's decomposition carve-out requires, so the docs `DECOMP` plans inline; `gate` in the args restores the approval loop; the docs phase's acceptance gate is `--waive`d at its `DECOMP` boundary; any normal stop ends the run. When the docs phase is `done`, run `rotate-backlog` once more and, on `archive`, sweep, commit and report. **One docs phase per invocation:** if that re-run prints anything but `rotate=archive`, relay it and STOP, so termination does not depend on every docs phase leaving no `## Doc impact` notes of its own. `archive-only`: `rotate-backlog --archive-only`, relay, STOP.
- **Release: workspace v54.** `WORKSPACE_VERSION = 54`, a `## v54 — <date>` CHANGELOG entry directly under the header with its **Migration notes** line, and the installer rebuilt with `--check` passing. P32's v53 entry slots between v54 and v52 at merge. P34's intent also claims v54: whichever of P33 and P34 lands on `main` second renumbers at its merge (the version line, the CHANGELOG heading, and every `v54` it added). See the operator question below.
- **Overlap with P32 and P34 is not a dependency.** Both edit `do-whole-phase`, `do-next-slice` and `CLAUDE.md` (P32: the executor section; P34: compact instructions and a skill reorder). P33 touches only the end-of-run archive line in each skill and the `CLAUDE.md` lines named for S2 below. The second phase to merge rebases on the other's text and keeps both changes.
