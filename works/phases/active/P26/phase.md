# Phase P26: Replace the Claude Design loop with a repo-file design contract and a design subagent

_Intent: see [intent.md](intent.md)._

## Objective

Define the on-disk design contract a separate web dashboard reads (each product repo holds its projects, rounds, numbered cards, tokens and decisions in git); add a dedicated design subagent that drafts rounds into it, using frontend-design only where it helps; rewrite design-cowork around the files, retiring the DesignSync read-back and SIGNOFF regroup and keeping Claude Design only as an optional bundle import; reword the executor hard rule to 'the design subagent drafts, the operator decides'; ship a hook that registers a repo with the dashboard. Governance unchanged (styles, rounds, literal signoff, mockup gate, RESPECT THE DESIGN); Claude Code only; no interim viewer (card files are opened directly); the dashboard is built in its own repo.

- **The contract, schema 1 (P26.S1)**; full text in the skill, and the relayable summary is at the end of `slices/P26.S1/result.md`:
  - **Root** `docs/reference/design/`, fixed. A repo's own `design/` tree is **no longer an alternative**, because the engine and the dashboard must find it unconfigured. **One project per repo**, identified by `design.json` = exactly `{schema: 1, id, name}`. `id` is `[a-z0-9-]` (≤ 63) and unique in the registry; it defaults to the repo folder's slug. Registry entries are per project, so multi-project can come in a later schema.
  - **Library** `cards/NN-slug.html`: numbered from 01, contiguous, sorted numerically, the path never changes, and a superseding card rewrites the same path. **Self-contained**: the only relative reference allowed is `../tokens.css` (inline or `https:` for the rest), so the same bytes render from a snapshot. Tokens are one `tokens.css` at the root.
  - **Marker**: line 1 is exactly `<!-- @dsCard key="value" … -->` over a **closed set**: `group` (required), `viewport` (`WxH`, required; mobile viewports stay valid) and `title` (optional, new: our dashboard can use it). The review address is `group="⏳ <slice> · <Group>"`: the **owning slice id**, as today.
  - **Rounds** `rounds/NN-slug/`: `round.json` (closed keys: schema, round, title, slice, status open/signed/superseded, opened_at, closed_at, cards, supersedes, signoff_words), plus `handoff.md`, `result.md`, `build-prompt.md`, optional `feedback.md`, `SIGNOFF.md` (signed only) and optional `import/` (a Claude Design bundle as-is). The record's `output/` subfolder is gone: the folder is flat.
  - **At most one open round per project.** While a round is open, the live cards carrying its address *are* the round (`cards` is filled at close).
  - **History = snapshot at close, not git refs:** the touched cards and `tokens.css` are copied, address on, into the round folder. That answers the regroup-erases-the-address gotcha. Closed rounds are immutable. `supersedes` is **derived** at close (for each touched card, the latest earlier closed round listing it), and readers compute the reverse link.
  - **Supersede** = `design-close <r> --superseded` (snapshot, no regroup). The cards stay addressed and the **next round of the same slice** inherits them; `design-open` refuses another slice while any is left.
  - **Registry** outside every repo: `$AGENTIC_DESIGN_REGISTRY`, default `~/.config/agentic-workspace/design-registry.json`, holding `{schema: 1, projects: [{id, name, repo, root, registered_at}]}` sorted by id, with absolute paths.
- **The commands (P26.S1):**
  - `design-init [--id] [--name]` writes the manifest.
  - `design-open --slug --slice [--title]` opens the next round and refuses while one is open.
  - `design-check [cards/NN-slug.html …]` checks everything and names every problem with exit 1. With the handoff's list it also runs the read-back check: listed cards are present and addressed, and added cards are numbered after the list.
  - `design-close <round> --words "…" | --superseded` runs snapshot → regroup (signed only; line 1 only, every later byte asserted identical) → manifest. It needs `SIGNOFF.md` first for `--words`, is idempotent, and resumes a half-landed run.
  - `design-register` upserts into the registry. It is idempotent, atomic, refuses an id another live repo holds, replaces an entry whose root vanished, and prints what it wrote.
  - All five are stdlib-only. `validate` does not call `design-check`.
- **The design subagent (P26.S2):** `.claude/agents/design-drafter.md`, `name: design-drafter`, `tools: Read, Edit, Write, Glob, Grep, Bash, Skill` (`Bash` for `design-check`, `Skill` for `frontend-design` on new-direction rounds only; no `DesignSync`, no web). **It tracks the high tier, and is not a third tier:** `executor_agent_files()` gained a third entry (label `design-drafter`, driven by `DESIGN_DRAFTER_FOLLOWS = "high"`), so `sync-agents`, the drift check, `validate`'s advisory warning and the `executor-mode` status line cover it with no other change. `EXECUTOR_TIERS`, `executors.toml` tables and the presets are untouched, so one economy/flex knob (and any `[claude.high]` override) governs every agent file and design work never lands on the mid tier.

Its verdict block: `status` (`done | needs_operator | blocked`), `round`, `cards_written`, `tokens_changed`, `frontend_design`, `departures`, `design_check`, `open_questions`, `blocker`.

- **The `design-cowork` loop (P26.S3)**; the full text is in the skill, and the governance audit is in `slices/P26.S3/result.md`. Per round:
  - **Inline:** `design-open` (plus `design-init` on a product's first round), then `handoff.md` with the numbered card paths and a `new visual direction: yes`/`no` line (the operator's call; the drafter's only licence for `frontend-design`).
  - **Dispatched:** `design-drafter` runs in the background; its prompt is only the round folder and the slice id.
  - **Inline read-back:** run `design-check <paths>` yourself, read the cards, `result.md` and `build-prompt.md`, then the concreteness check. Commit `drafted`, then **PENDING #1**.
