# P31.F1 result: architecture fix, narrow the workflow/ refusal

## Step 1: the truth, from the code (read only, installer not run)

`resolve_layout()` in `installer/main.py` (lines 97-130):

- `if RETROFIT: return False` comes first. `RETROFIT` is `--into-existing` (`INTO_EXISTING=1`, line 29). An `--into-existing` run therefore takes the at-root path before the marker check and is **not covered**.
- The refusal is `if os.path.lexists(t / NESTED_MARKER) and (UPDATE or not AT_ROOT_FLAG)`. On a target that holds `.agentic-nested.json` itself, that means:
  - a bare install, with or without the redundant `--nested`, refuses (`not AT_ROOT_FLAG`);
  - any `--update` refuses, `--update --at-root` included (`UPDATE`);
  - `--at-root` without `--update` is **not covered**. It falls through to the at-root path's own guards, such as the "target already contains managed workflow files" refusal (line 1249). That is a different refusal, so the architecture sentence does not claim it.
- The wrapper rules out `--update` together with `--into-existing` (`installer/wrapper.sh` line 86), so the two never meet.

This matches P29's recorded resolution: `works/phases/active/P29/phase.md` line 46 ("on any `--update` or a fresh nested install → refuse") and line 55 ("a bare install or an `--update` on a nested install's own `workflow/` (S1's resolution: `--at-root` and `--into-existing` are not covered), not as 'any run'"). It also matches decisions v0043's P29 entry ("so does a bare install or `--update` run on a nested install's own `workflow/` directory").
