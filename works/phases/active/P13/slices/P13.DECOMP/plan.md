# P13.DECOMP — Codex Workflow Parity

Create five bare, sequential, high-risk implementation slices for the confirmed non-visual Codex parity work. Do not dispatch an executor for this decomposition and do not prefill any middle slice's `plan.md`.

1. `P13.S1` determines and lands the Codex executor tiers, including official custom-agent model/effort choices, routing, escalation, configuration, attribution, contracts, and the rebuilt installer artifact. The orchestrator is explicitly authorized to execute this slice inline.
2. `P13.S2` restores Codex `do-whole-phase` as an auto-only workflow, rejecting `gate` and `plan only` while preserving execution of legacy `ready` slices.
3. `P13.S3` aligns Codex `do-next-slice`, all other non-visual mirrored command skills, and the equivalent `AGENTS.md` / `CLAUDE.md` contract around auto-only execution, routing, escalation, and actual-model attribution.
4. `P13.S4` ships the parity work through fresh install, retrofit, and update flows, including managed-path behavior, versioning, documentation, and the generated artifact.
5. `P13.S5` closes regression coverage and audits remaining live non-visual Claude-only assumptions.

All five slices use `kind: implementation`, `risk: high`, orders 1–5, and a linear dependency chain. Record the breakdown and both inline exceptions in `phase.md`, write a free-form decomposition result, validate, finish the slice, confirm `next` selects `P13.S1`, and commit the slice boundary.

P14 exclusively owns the visual-design cowork replacement. Codex supports automatic execution only: unsupported modes fail clearly, and existing `ready` slices remain executable for upgrade and cross-tool compatibility.
