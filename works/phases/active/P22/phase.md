- **Order: S1 before S2, deliberately.** S1 lifts the 16 KB notebook squeeze, so S2 -- the notes-heavy slice -- writes its state into a notebook that no longer forces compression. This phase's own evidence (four P21 slices had to compress unrelated content to land) is the argument. (P22.DECOMP)
- **D14 shape (from `intent.md`, not re-decided here).** Every durable doc carries an explicit last-updated marker -- **source commit, date, consolidating phase** -- recorded in `docs/index.json` and surfaced where agents actually read docs (the `workflow.py docs` listing and/or a generated header on `docs/current/*.md`), plus doctrine: a doc whose last update predates the owed `## Doc impact` notes is **stale evidence to check against the notes, never current truth**. (P22.DECOMP)
- **No cadence knob, by operator decision.** Docs phases run only when the operator asks. `CONSOLIDATION_DEBT_MIN_PHASES` stays `1` unless the work turns up a contradiction -- and if it does, `S2` says so rather than tuning it silently. Explicit staleness is what the operator took *instead of* a cadence. (P22.DECOMP)
- **D15 shape.** Replace `PHASE_MD_BUDGET = (200, 16*1024)` with one generous **byte** cap standing in for ~100k tokens (~400 KB of text). The line ceiling **goes**: P21 measured that it never binds (69 % of 200 lines vs 92 % of 16,384 B). Warning-only, never an error -- unchanged. `finish-slice` keeps printing the size (lines *and* bytes are fine to print; only bytes judge). (P22.DECOMP)
- **D16 shape.** Sharpen keep-tests-small to **core-only**: test files exist for very core behavior (logic the product cannot afford to break), never for style/cosmetic/trivial surface -- that is verified live (running it, smoke checks, the real-browser sweep). Tests stay very small. The rule text lives in exactly **one** place in the machinery -- `CLAUDE.md` Hard Rules -- plus `docs/current/qa.md` as durable truth; the two executor agent files do **not** restate it (checked at DECOMP). (P22.DECOMP)
- **D14/D15/D16 are closed by dropping, not promoting, at review-pass time.** Their titles are the *superseded questions* ("state a cadence", "decide the budget's shape", "decide whether the rule grows teeth"), and the operator answered all three differently -- so a promotion would bind a slice to a question that no longer exists, and `promote-deferred` would also create a slice this phase already has. Commands for the orchestrator at the pass: `python3 scripts/workflow.py drop-deferred D14 --reason "resolved by P22"` (same for `D15`, `D16`). Executors never run them. (P22.DECOMP)
- **Workspace version v39, one CHANGELOG section, opened by the first shipping slice.** `WORKSPACE_VERSION` lives at `installer/main.py:38` (currently 38). `S1` bumps it to 39 and opens a single `## v39` section; `S2` appends its bullets to that same section and owns the lead **"Why this release"** bullet (D14 is the headline).
