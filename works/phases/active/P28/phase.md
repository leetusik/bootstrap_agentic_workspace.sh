# Phase P28: Nested personal install

_Intent: see [intent.md](intent.md)._

## Objective

Let one engineer run this workspace privately inside a host repo they don't own, with no team-visible footprint. The engine and state live in a nested git repo at /workflow, hidden by .git/info/exclude. Skills and executors go into the host's .claude/ as untracked files, with clashing names detected and prefixed at install. Personal settings go in settings.local.json and the contract pointer in CLAUDE.local.md. Nothing is written to CI, .gitattributes or docs/. Slice commits split in two: product code to the host repo in its recorded commit convention (asked once at install), state to /workflow. phase-scope reads the host repo's base commit. Parallel worktrees are off in nested mode. Contract and skill paths carry the /workflow prefix, and an --update path covers nested installs. The acceptance walkthrough waits for a run in the real company repo.

**Design direction (slices may refine, never silently reverse).**
1. **Marker `workflow/.agentic-nested.json`** (renamed from `nested.json` by the operator's answer, done in S2), written by the installer, read by the engine: `host_root` (relative, `..`); host commit convention (`inferred`, `confirmed: true|false`, `coauthor_trailers: allowed|forbidden|unknown`); the skill/agent **rename map** from clash detection. Absent → at-root mode.
2. **Paths rewritten once, at install**, in the installed contract, skills, agents and the `settings.local.json` allowlist: `python3 scripts/workflow.py` → `python3 workflow/scripts/workflow.py`; `works/`, `docs/current/`, `docs/versions/`, `docs/index.json` get the `workflow/` prefix. Exact-token substitution with a **post-check** (no unprefixed engine command remains). The engine prints host-relative paths when nested.
3. **Name clashes:** a renamed skill/agent is rewritten only in slash references, skill-name references and `subagent_type`/filename/`name:` uses — **never** in `workflow.py <subcommand>` lines. The engine resolves agent filenames through the map. Per CC docs: a skill rename changes its directory **and** its `name:` frontmatter (all 18 shipped skills set `name:`); an agent rename changes its `name:` frontmatter (that *is* the `subagent_type`; the filename "doesn't have to match") and, by convention, its filename.
4. **Nested deltas live in one generated file, `<host>/CLAUDE.local.md`**: it imports the rewritten contract and states the nested rules (two commits per slice, the product commit in the host's recorded convention + the trailer rule; no parallel; PRs carry no phase IDs or workflow paths). Skills stay mode-neutral apart from the path rewrite. **Refined by the verification:** the import is `@workflow/CLAUDE.workspace.md` (the existing retrofit sidecar name), **not** `@workflow/CLAUDE.md` — a `CLAUDE.md` in a subdirectory is auto-loaded on demand whenever Claude reads/edits a file there, risking a second copy of the contract (the docs never say imported files are de-duplicated against it). So nothing under `workflow/` is named `CLAUDE.md`/`CLAUDE.local.md`, and `workflow/` holds no `.claude/skills|agents` (nested `.claude/skills` also load on demand, as `/workflow:<name>` duplicates). The `@` line stays outside backticks/fences (import parsing skips code). **Fallback** if S2's live `/context` check shows the import not expanding: inline the rewritten contract into `CLAUDE.local.md`. The `~/.claude/CLAUDE.md` fallback from `intent.md` is not needed.
5. **"Ask once" happens after install.** The installer is non-interactive (`curl | sh`): it infers the convention from the host's `git log` + `CONTRIBUTING*` and writes `confirmed: false`; a new engine command (`nested-convention`, show / `--confirm …`) records the operator's confirmation; until then the orchestrator asks before the first product commit.
6. **Updates:** `--update --nested` refreshes the machinery under `workflow/` and re-renders the host-side files with the same guarantees; `/update-workspace` detects a nested install (`workflow/.agentic-nested.json` under cwd).
7. **Sessions start at the host root** (cwd = `<host>`). Starting inside `workflow/` makes the nested repo the "repository root", so the host's `.claude/` skills and agents are not found; starting in a host subdirectory makes the `@workflow/…` import "external" (one-time approval dialog). Nested mode runs in the main host checkout only: untracked files (`CLAUDE.local.md`, `.claude/` additions, `workflow/`) do not exist in host worktrees — consistent with parallel being off.

**Engine contract (P28.S1; S2 writes to it, the review checks it).**
- **`workflow/.agentic-nested.json` schema 1** (`NESTED_MARKER`; `nested_marker_problems` in `scripts/workflow.py` is the checker): `{"schema": 1, "host_root": "..", "commit_convention": {"inferred": "<text>"|null, "confirmed": false, "text": null, "coauthor_trailers": "unknown"}, "renames": {"skills": {}, "agents": {}}, "installed": {"skills": [...], "agents": [...]}}`. The first four keys are required, and so are all four convention keys. `installed` (P28.S2) is optional but strict when present: exactly `skills` and `agents`, each a list of distinct bare names, and every `renames` value must be listed in it; the installer always writes it. `host_root` is relative and resolves to a strict ancestor of the engine root. `coauthor_trailers` ∈ `allowed|forbidden|unknown`; `confirmed: true` needs non-empty `text` and `allowed|forbidden`. `renames.<kind>` maps the original name to a bare installed name (no `/`, no leading `.`). Unknown top-level keys only warn. A marker that exists but is malformed fails `validate`, and every other command refuses: it is never read as at-root mode.
- **`phase.json` `host_anchors`** (nested only, read defensively): `{"created": <host HEAD at new-phase, or null when the host had no commit>, "review_pass": <host HEAD at review-phase --verdict pass>}`, placed after `acceptance`. Closed keys; each value is a hex SHA or null. `phase-scope` measures `created..review_pass|HEAD` in the host with pathspec `. :(exclude)workflow` (the host's own `docs/`/`works/` are product). A null anchor measures from the empty tree; an absent anchor lists only the working tree and suggests `--base`.
- **Printed vs stored paths.** Output is host-relative (`shown()`, `WORKFLOW_CMD` = `python3 workflow/scripts/workflow.py`); stored paths stay ROOT-relative. The engine also prints design paths as `workflow/docs/reference/design/...`.

**Nested installer (P28.S2; `installer/main.py`, `sh bootstrap_agentic_workspace.sh <host> --nested`).**
- **Rewrite** (`nested_rewrite(text, renames)`, applied to the source payload only; a second pass is a no-op): `scripts/workflow.py` → `workflow/scripts/workflow.py` (allowed-tools and the allowlist too); `works/`, `docs/current`, `docs/versions`, `docs/reference`, `docs/index.json`, `docs/README.md`, `executors.toml`, `.env` → under `workflow/`. Token bound: never after `[\w./-]`, so `workflow/works/`, URLs, `<repo>/scripts/…`, `networks/` and the upstream `docs/retrofit-guide.md` stay. Applied to the host's skills and agents, `settings.local.json`, `workflow/CLAUDE.workspace.md` and `workflow/works/templates/*`. Not applied to `workflow/executors.toml`, `workflow/docs/README.md` or the doc seeds.
- **Contract references:** `` `CLAUDE.md` `` becomes `` `workflow/CLAUDE.workspace.md` `` only after "read"/"Read"/"see"/"See", inside "contract (" or "contract — ", or as a bare `- ` list item (6 sites: create-phase, design-cowork, do-next-slice, do-whole-phase, parallel-phase, review-phase). The executors' and drafter's "repo-specific safety rule in `CLAUDE.md`" stays: in a host repo that is the team's file. The retrofit and update-workspace texts also stay.
- **Renames** (never inside a `workflow.py …` command span):
  - a skill X→Y changes in `/X`, `.claude/skills/X/`, "`X` skill" (bold too), its own `name:` frontmatter and its directory; a hyphenated skill-only name (not an engine subcommand: create-phase, design-cowork, do-next-slice, do-whole-phase, parallel-phase, rebuild-workflow, update-workspace) also as `` `X` ``;
  - an agent X→Y changes as every token (its `name:`, `subagent_type:`, `.claude/agents/X.md`, prose) and its filename.
- **Clash rule:** a name counts as taken when a host entry that is not ours uses it as its directory/file name or its `name:` frontmatter. Entries are read from `.claude/skills/*`, `.claude/agents/*.md`, and for skills also `.claude/commands/**/*.md` (a skill would shadow the team's command). A clashing name installs as `wf-<name>`; if that is taken too, the install refuses. A personal `~/.claude/skills/<installed>` only warns.
- **Ours on `--update`:** recognised by the marker's `installed` record. Existing renames and unrenamed installed names are kept. Only names not installed before (newly shipped) are clash-checked. Ours that are no longer shipped stay in `installed` and in the exclude block while on disk, and are reported as stale, never deleted. An unconfirmed convention is re-inferred; a confirmed one is kept.
- **Tracked-target refusal:** before any write, `git ls-files` over every host target (skill dirs, agent files, `CLAUDE.local.md`, `.claude/settings.local.json`); a tracked one refuses the install and is named. Also refused, all with nothing written: a host that is not a git work-tree root; a tracked `workflow` path; a non-empty `workflow/` (`.git` allowed); an unparseable `settings.local.json`; a stray block marker; a failed post-check (an unprefixed engine command or workspace path, or a renamed name left in `/X` or `subagent_type:` form).
- **Exclude block:** in `git rev-parse --git-path info/exclude`, one `# BEGIN agentic-workspace (nested)` … `# END …` block, replaced in place and never duplicated. It holds `/workflow/`, `/CLAUDE.local.md`, `/.claude/settings.local.json`, `/.claude/skills/<installed>/` and `/.claude/agents/<installed>.md`. `CLAUDE.local.md` gets one `<!-- BEGIN/END agentic-workspace (nested) -->` block, and the operator's own text is kept. A replaced existing file keeps its mode.
- **Live check (2026-10-07, CLI 2.1.292, scratch host):** `claude -p` at the host root reported `CLAUDE.md`, `CLAUDE.local.md` and the imported `workflow/CLAUDE.workspace.md` as loaded, and quoted its rewritten Read Order line. **The `@import` expands, so decision item 4's fallback is not needed.** The executor-side check stays docs-only.

**Claude Code verification (P28.DECOMP; docs fetched 2026-10-07, local CLI 2.1.292; docs only, no live probe — S2's live run confirms with `/context`).**

[sub-agents](https://code.claude.com/docs/en/sub-agents), [skills](https://code.claude.com/docs/en/skills)
- **`settings.local.json`** sits above `settings.json`; permission arrays merge across scopes; Claude Code adds it to the *global* git excludes only when **it** creates the file — an installer-written file must be excluded by us (`info/exclude`). Read at the repo root when started in a subdirectory. [settings](https://code.claude.com/docs/en/settings)
