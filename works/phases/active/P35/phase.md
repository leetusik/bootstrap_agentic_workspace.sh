10. **A nested phase worktree is a pair (P35.S2, observed).** The host worktree goes at `<host>/.claude/worktrees/P<N>-<slug>`, with the nested worktree at `<host-wt>/workflow` on `phase/P<N>-<slug>`. The engine there resolves HOST_ROOT to the host worktree and claims the stream with no other change. `/.claude/worktrees/` must be in the **host's** common `info/exclude`; without it the host shows `?? .claude/`.
11. **Teardown is nested-first (P35.S2, observed).** `git worktree remove` on the host worktree exits 0 and silently deletes the nested worktree inside it (`workflow/` is ignored in the host), including untracked `works/` files. The order is: the nested worktree first, then the host worktree. Ignored files in either worktree are deleted without refusal, so teardown lists them and refuses first. A commit on a detached host worktree is orphaned at removal, so detached host commits are guarded.
12. **Host-worktree wiring (P35.S2, observed + documented).** `parallel-start` copies `<host>/CLAUDE.local.md` into the host worktree. Without the copy the main file loads as an ancestor, but its `@workflow/…` import is not expanded, so the session gets no contract. Nothing is created under `<host-wt>/.claude/`: skills, agents and `settings.local.json` read through from the main checkout. The engine's `CLAUDE_AGENTS` resolves to the main host checkout, not HOST_ROOT.
13. **The compaction hooks resolve the engine from the hook's stdin `cwd` (P35.S2, observed + documented; at root too).** `$CLAUDE_PROJECT_DIR` stays at the main checkout after EnterWorktree, so today a worktree session resumes on the default stream's pointer. The fix lives in the engine, so the hook commands stay as they are.
14. **`parallel-start` re-stamps `host_anchors.created` to the host worktree's base sha (P35.S2, observed).** A stale anchor from `new-phase` makes `phase-scope` list `main`'s commits from between `new-phase` and `parallel-start`. `review_pass` and `_phase_scope_nested` need no change.

## Operator Questions

_Questions only the operator can answer. Append only; every entry is routed at the review — folded into the acceptance walkthrough or filed with `defer-job`. An unrouted entry is a review finding._

- **(P35.S2) Host branch naming in a nested worktree phase.** S2 recommends that the operator names the branch at each start: `parallel-start <P> --host-branch <name>` is required in nested, and the orchestrator asks for the name. An existing branch that is not checked out is reused. The alternatives:
  - the orchestrator derives a name. `nested-convention` describes commit subjects, not branch names, so there is nothing to derive from;
  - a detached host worktree. Observed: host commits made there are orphaned at teardown.

  Which rule do you want?
- **(P35.S2) Default base for the host worktree.** S2 recommends the main host checkout's `HEAD`: it needs no fetch, matches the engine's "start from the latest commit", and `--host-base <ref>` overrides it. The alternative is the host's default branch (`origin/HEAD`, Claude Code's own "fresh" default), which suits a PR cut from a clean upstream. Which default do you want?
