## Decisions

_Durable cross-slice decisions. Replace a superseded line; never stack versions._

1. **Breakdown (P35.DECOMP).** Research first, build cut later: `S1` docs/low (order 10, pinned wording, no design: the mid tier on the cheap row); `S2` research/high (20, open design: the paired nested worktree lifecycle); `S3` research/high (30, open design: the repo conversion, proven on a scratch clone); `DECOMP2` decomposition/high (40, cuts the build from S2+S3, never pre-planned); `REVIEW` gated. Estimate: one mid dispatch, two research dispatches, DECOMP2, then the build slices DECOMP2 cuts and the review. S3 depends on S2 only for dispatch sequencing, not its findings.
2. **Opt-in stays (v43).** "parallel" / "parallely" / "in a worktree" on `/do-whole-phase` / `/do-next-slice` is the operator's word, and in a nested install it now runs the phase in its own worktree. Worktrees never start unasked, and never for a docs phase.
3. **Nested stream key = the nested repo's branch.** The host branch is named from the host's custom and carries no workspace IDs; the host side is integrated by that custom (Decision 18), never by an engine merge into the host default.
4. **The conversion is for this repo only.** No migration command ships; v50's "nothing migrates an at-root install" stands for adopters. "This upstream repo stays at-root" (`decisions.md:121-122`, `installer/README.md:90`) is superseded by the operator on 2026-10-13 (Doc impact note below).
5. **The conversion moves the shipped sources out of the live paths** (`.claude/skills`, `.claude/agents`, `.claude/settings.json`, `CLAUDE.md`, `works/templates`, the `executors.toml` seed, `.github/workflows/workspace-ci.yml`, `.gitattributes`, possibly `scripts/workflow.py`), so the nested install's active copies own `.claude/` and the session contract. The exact source tree is S3's to find.
6. **glide-ilab is reference only:** read-only over `ssh node`, never written; it picks the release up later via `--update`.
7. **Gate: required.** The operator runs a nested phase in a worktree and uses this repo in its new layout. Surface: a scratch nested install driven through a paired-worktree phase from start to teardown, the main backlog's Streams view, and this repo after conversion. Review boundary: `phase-scope P35`.
8. **Doc impact expected** (each a one-line note when the change lands; a docs phase pays them): architecture (Nested Install, parallel mode), operations (parallel runbook, idle-window prep l.1597-1670, upstream dev loop), decisions (superseded at-root line, nested parallel), qa (smoke tests).
9. **Deferred jobs (P35.DECOMP):** D35, D57 and D37 were weighed by S2 (f), (g), (i); resolved in Decision 21.
10. **A nested phase worktree is a pair (P35.S2, observed).** The host worktree goes at `<host>/.claude/worktrees/P<N>-<slug>`, with the nested worktree at `<host-wt>/workflow` on `phase/P<N>-<slug>`. The engine there resolves HOST_ROOT to the host worktree and claims the stream with no other change. `/.claude/worktrees/` must be in the **host's** common `info/exclude`; without it the host shows `?? .claude/`.
11. **Teardown is nested-first (P35.S2, observed).** `git worktree remove` on the host worktree exits 0 and silently deletes the nested worktree inside it (`workflow/` is ignored in the host), including untracked `works/` files. The order is: the nested worktree first, then the host worktree. Ignored files in either worktree are deleted without refusal, so teardown lists them and refuses first. A commit on a detached host worktree is orphaned at removal, so detached host commits are guarded.
12. **Host-worktree wiring (P35.S2, observed + documented).** `parallel-start` copies `<host>/CLAUDE.local.md` into the host worktree. Without the copy the main file loads as an ancestor, but its `@workflow/…` import is not expanded, so the session gets no contract. Nothing is created under `<host-wt>/.claude/`: skills, agents and `settings.local.json` read through from the main checkout. The engine's `CLAUDE_AGENTS` resolves to the main host checkout, not HOST_ROOT.
13. **The compaction hooks resolve the engine from the hook's stdin `cwd` (P35.S2, observed + documented; at root too).** `$CLAUDE_PROJECT_DIR` stays at the main checkout after EnterWorktree, so today a worktree session resumes on the default stream's pointer. The fix lives in the engine, so the hook commands stay as they are. **Built in P35.S6:** `_hook_stdin_or_redirect` reads stdin once. When `AGENTIC_HOOK_REDIRECTED` is unset and the walk up from `cwd` (`d/workflow` checked before `d`, each needing `scripts/workflow.py` + `works/`) finds an engine that is not `__file__`, it re-runs that engine with the same stdin, `cwd=d`, the guard set and a 12 s timeout, and relays its stdout and stderr. Any error, timeout or non-zero exit falls back to this engine, with nothing relayed.
14. **`parallel-start` re-stamps `host_anchors.created` to the host worktree's base sha (P35.S2, observed).** A stale anchor from `new-phase` makes `phase-scope` list `main`'s commits from between `new-phase` and `parallel-start`. `review_pass` and `_phase_scope_nested` need no change.
15. **The source tree holds no live names (P35.S3, observed + documented).**
    - The shipped sources move to one tree: `payload/` at the root (the operator, 2026-10-13).
    - Each source sits at its emit path with the first component undotted (`claude/skills`, `claude/agents`, `claude/settings.json`, `github/workflows/workspace-ci.yml`, `gitattributes`), and `CLAUDE.md` becomes `contract.md`. Reason: Claude Code loads a subdirectory's `.claude/skills/` and `CLAUDE.md` on demand.
    - `scripts/workflow.py` moves too. A root copy with no `works/` answers `next` wrongly and creates a root `works/` on `rebuild`.
    - Emit paths are unchanged, so the artifact is byte-identical.
16. **The conversion runs: host commit, then install, then history attach (P35.S3, observed).**
    - The installer refuses (at `nested_verify_clean`) while the source moves out of `.claude/` are staged but uncommitted. So the host commit lands first.
    - Then a fresh nested install. Then the stashed root state is overlaid into `workflow/`, and the history from `git filter-branch` (331 → 292 commits) is attached with `git -C workflow reset --soft <extracted tip>`. The result is one linear commit.
    - P35 needs `host_anchors.created` stamped to its at-root creation commit's parent (`8ea3b7bf…`), or nested `phase-scope` has no base.

    - `S7` implementation/low, 80: the `## Streams` view and the D57 in-flight filter on `next`. The design is pinned in S2 (g).

18. **PR policy is the host's custom; the engine is policy-neutral in nested (operator, 2026-10-13).** In a nested install the engine never pushes, opens a PR or merges into the host default. `nested-convention`'s confirmed text covers **commits, branches and PRs** (broadened from commits). The orchestrator follows it at `parallel-start` (the branch name) and at integration (one PR per phase, or a ticket's phases folded onto one branch by rebase with the checks re-run on the combined commit), and asks where the text is silent. At-root installs are unchanged: the local merge into main, push → PR on request. Reason: "this repo is not only for my use case."
19. **Host branch and base (operator, 2026-10-13).** In nested, `--host-branch` is required; the orchestrator proposes a name from the custom, the operator confirms, and the engine never invents one. An existing branch is reused only if it is not checked out (`host_branch_created` records which). `--host-base` defaults to the host's default branch, resolved as: `git symbolic-ref refs/remotes/origin/HEAD`, else `init.defaultBranch` if that branch exists locally, else `main`, then `master`, else refuse with "pass --host-base". The engine itself never fetches; the skill fetches first when the custom says to. This **supersedes S2's pick** (the main checkout's `HEAD`), because a nested main checkout is often on another session's in-flight branch (glide-ilab P15 was on `feat/signal-tables-schema`). Teardown keeps the host branch, deleting it only when the engine created it and it has 0 commits beyond its base.
20. **The conversion's execution (S10; operator, 2026-10-13).** S10's plan is made at the gate (plan mode, operator approval) whatever the run's mode. The executor does the working tree (S3 (f) step 2). The orchestrator runs S3 (f) steps 0, 1 and 3-8 inline with the operator present, with the tag + bundle backup and the `mv`-only rollback ready: a **one-time exception** to "every slice is delegated", stated in S10's `plan.md`. Host commit subjects carry no phase/slice IDs from the conversion commit on (`docs(engine): …`); the IDs stay in the nested repo's commits, and `Co-Authored-By` stays (trailers allowed). S10 ends `pending` for the operator to restart Claude Code at the repo root; S11 and the REVIEW run in that session from `workflow/works/phases/active/P35/`.
21. **Deferred jobs (P35.DECOMP2).** **D57 folds into S7** (same root cause and fix: the in-flight filter on `parallel_phases_elsewhere`); the orchestrator closes it when S7 lands. **D35 stays deferred** (a rebase during the PR needs an upstream-ref policy; its trigger has not fired; the S4 re-stamp removes the at-start drift). **D37 stays deferred** (design-specific; its trigger, the first nested design phase, has not fired; `execution.host_branch` gives its fix a named branch). New candidate for the orchestrator to file: "shared scratch paths linked into phase worktrees" (S2 (e)), in `slices/P35.DECOMP2/result.md`.
22. **Nested `parallel-start` as built (P35.S4).**
    - A missing `--host-branch` is refused first, writing nothing. `--host-branch` and `--host-base` are refused at root.
    - `--worktree` overrides the **host** worktree's path, and the nested half sits at `<it>/workflow`.
    - The host exclude line is anchored (`/.claude/worktrees/`), and either form counts as present.
    - `execution.worktree` is the nested worktree. The five `host_*` keys (`host_worktree`, `host_branch`, `host_base`, `host_base_sha`, `host_branch_created`) appear together and only in nested; `validate` enforces both. `base_branch` comes with them in nested, but is only type-checked at root, so S7 may stamp it there.
    - `host_anchors.created` is the base sha for a new branch, or `merge-base <base> <branch>` for a reused one.
    - `parallel-skip` runs in nested too.
    - `CLAUDE_AGENTS` is the common git dir's parent, but only when that dir is named `.git`; otherwise it falls back to HOST_ROOT.
23. **Nested teardown as built (P35.S5).** `NESTED_PARALLEL_OFF` and `_refuse_parallel_when_nested` are gone; every parallel command runs in nested.
    - Guards first, one combined refusal, nothing touched: uncommitted nested or host work; ignored worktree-only files in both worktrees (host minus `CLAUDE.local.md` and `workflow/`), refused unless `--discard-ignored`; a detached host HEAD with commits beyond `host_base_sha` that **no branch, tag or remote ref holds** (the orphan case only).
    - No `--force` anywhere: git deletes ignored files without it (observed, git 2.45.2), so git's own untracked/modified refusal stays a second check. `--discard-ignored` is refused at root.
    - Then the nested worktree, the host worktree (each pruned instead when already gone but registered, **before** the branch steps: a stale registration holds its branch), `branch -D` the host branch only when engine-created, 0 commits beyond its base and checked out nowhere else, then `branch -d phase/…`. A failure prints the remaining commands; a re-run resumes.
    - `worktree` and `host_worktree` become null; the other host keys and `base_branch` stay. Merge-finish, consolidated and gate run in ROOT (the nested repo) and never touch the host.
24. **The Streams view and the in-flight filter as built (P35.S7).** One predicate, `phase_in_flight`: a parallel execution block AND (`execution.worktree` not null OR status not `done`). It gates three things, at root and nested alike.
    - `## Streams` in `backlog.md`, right after `## Pointer` (`streams_section`). Columns `Stream | Phase | Status | Current slice | Done | [Host branch, nested only] | Worktree | Source`. Order: this checkout's own parallel stream first (working tree), then `default`, then one row per other in-flight phase. The default row is the working-tree pointer on the default stream; on a parallel stream it is `_phases_at_ref(execution.base_branch)` (source `branch <base>`), else the local copy (`local copy`). Other rows read `branch`, then `origin/branch`, else the local copy. The status cell is the short half of `_parallel_verdict_pair` (the long half is `parallel-status`'s sentence: one decision tree). Worktrees print relative to the host root (nested) or ROOT, so the tracked file carries no home path. With nothing stamped and in flight, the only git call is `current_stream`'s existing one.
    - `next`'s `parallel_phases_elsewhere` skips a stamped phase that is `done` with its worktree torn down (closes D57; P33 here no longer listed).
    - `consolidation_debt_line` (`next`, `validate`) skips a stamped phase whose status is not `done`: `parallel-start` stamps `execution.consolidation: "pending"` at start, but it owes nothing until its review passes. A `done` phase (merged or not, torn down or not) owes as before. `phases_owing_consolidation` and the archiving guard are unchanged.
    - Root `parallel-start` also stamps `execution.base_branch` (additive; `validate` type-checks it).

## Operator Questions

- **(P35.S2) Host branch naming in a nested worktree phase.** S2 recommends that the operator names the branch at each start: `parallel-start <P> --host-branch <name>` is required in nested, and the orchestrator asks for the name.   - the orchestrator derives a name. `nested-convention` describes commit subjects, not branch names, so there is nothing to derive from;
  - a detached host worktree. Observed: host commits made there are orphaned at teardown.

  Which rule do you want?
- **(P35.S2) Default base for the host worktree.** S2 recommends the main host checkout's `HEAD`: it needs no fetch, matches the engine's "start from the latest commit", and `--host-base <ref>` overrides it. The alternative is the host's default branch (`origin/HEAD`, Claude Code's own "fresh" default), which suits a PR cut from a clean upstream. Which default do you want?

- **(P35.S3) The source tree's name.** The shipped sources leave the live paths, and the tree needs a name.
  - S3 recommends `payload/` at the root: it is visible to contributors as "what ships", and a single constant in `build.py` and the smoke suite names it.
  - The alternatives are `src/`, or `installer/payloads/tree/` beside `doc_bodies`. The latter means the hook's `^installer/` already covers it, but the sources are buried.

  Which name do you want?
- **(P35.S3) Who runs the switch.** After the host commit, there is no root engine until the nested install exists. The install needs that host commit first. An executor never commits in any repo.
