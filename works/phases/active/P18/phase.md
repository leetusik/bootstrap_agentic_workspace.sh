## Decisions

- **The installer rebuild rides every slice that touches an embedded file** (`scripts/workflow.py`, `.claude/*`, `works/templates/*`, `CLAUDE.md`): S1–S4 each run `python3 installer/build.py` before returning, because the tracked pre-commit hook runs `installer/build.py --check` on every commit. S5 owns only the version bump + CHANGELOG.
- **A new embedded file must be registered in four places** or the build/tests fail: `FIXED_LIVE_FILES` (`installer/build.py`), `MANAGED_FILES` (`installer/main.py`), the emitted fresh-install writer (`installer/main.py`), and the hand-maintained `DUAL_FIXED` manifest in `tests/retrofit_smoke.sh` — Test 6 parses `FIXED_LIVE_FILES` by AST and fails when the manifest drifts.
- **`works/templates/` is machinery in the update policy**, so adopters get the new template on `--update` while every existing `works/phases/**/phase.md` is preserved. That is why the marker-less path is a **silent no-op, never a migration**.
- **A marker counts only when it is alone on its line** (P18.S1): the first implementation matched the literal anywhere and spliced the generated table into a prose cell that quoted it. Notebooks may discuss the markers freely — this one deliberately still does, in the S4 note below, keeping the live regression case the decomposition table used to provide.
- **The `## Slices` writer writes only on change** — `write_text()` always rewrites (atomic replace, no unchanged-content skip), so a read → splice → compare guard is what keeps `next`/`rebuild` from dirtying every notebook.
- **`phase.md` is not in `GENERATED_FILES`.** Only the marker block is generated; `parallel-merge-finish`'s "resolve by taking either side" advice must never apply to the whole notebook. Correct guidance for a conflict *inside* the block: re-run `rebuild` (S3 adds that line to the `parallel-phase` skill).
- **`- Rebuilt at:` is gone from the two markdown dashboards only** (P18.S2) — `index.json.last_rebuilt_at` and `state.json.updated_at` stay (operator-confirmed, `intent.md` part 3), and `rebuild` still rewrites `docs/index.json`'s timestamp. `rebuild_deferred_dashboard`'s now-readerless `rebuilt_at` parameter was **removed**, not kept: its only caller is `rebuild_index_and_state` (`cmd_deferred` reaches the dashboard through that, not directly — the DECOMP note's "two call sites" was wrong).
- **The budget warning skips a `done` phase** (P18.S2): its notebook is closed history waiting to be archived, so "rewrite it under budget" is advice nobody can act on. The check still bites through `in_review`, which is where the review reads it. Without the skip this repo's own `validate` would warn about pre-v35 `P17` (446 lines / 32850 bytes) on every run, in the middle of P18's review.
- **Both new `validate` checks are warnings, never errors** (`intent.md` clarification 4): `validate()` keeps `warnings` and `errors` in separate lists, prints warnings first, and still exits 0 with warnings.
- **Gate:** `accept-gate P18 --waive` (workspace machinery, no operator-visible product surface). This repo has no `## Operator Runtime` section and needs none — do not add one in this phase.
- **The two executor tiers are single-sourced by copy** (P18.S3): they are byte-identical below their frontmatter, so a body edit lands in `slice-executor-high.md` and is copied into `-mid.md` (frontmatter kept); `diff <(tail -n +9 …mid) <(tail -n +9 …high)` is the drift gate, and `sync-agents --check` only covers the frontmatter.
- **The executor prompt grew 18442 → 21651 bytes** (+3.2 KB per dispatch, P18.S3) to carry the notebook protocol. Deliberate and strongly net-negative in tokens: it is what buys dropping the whole-doc-set read (330 KB) and `docs/index.json` (54 KB) from every dispatch, plus a notebook capped at 16 KB instead of P15's 819 lines.
- **New prose invariants are pinned as asserts inside Test 0's existing python block** (P18.S3, again in S4 for the contract), never as new `ok` lines — the smoke count stays **137**, and wording this phase supersedes is pinned as a negative rather than merely deleted.
- **The contract could not both carry the new protocol and stay ≤ 33383 bytes** (P18.S4): `CLAUDE.md` is now **34419** (+1036, +3.1 %). The plan assumed the rewritten Read Order would be *shorter* than the old one; it is **+173**, because the old four lines were bare pointers while the new three carry the discipline itself (just-in-time, sections not documents, the two never-reads). Per-touch-point deltas and the compression already spent are in `P18.S4/result.md`; the ~700 bytes of true duplication still left (the executor/orchestrator division stated in both *Driving This Workspace* and *Hard Rules*) is deferred job **D8**'s work, not this phase's. The review accepts the overage or cuts a fix slice.
- **P18's own `phase.md` is the migration test bed:** S1 migrated it in place (this file); S2–S5 edit it under the new rules, and the review measures the result.

## Doc impact

_One line per durable-truth change: `- <doc>.md: <what changed> (<slice>)`. Append only; consolidated into versions at the review, never per slice._

- operations.md: phase notebook is seeded from `works/templates/phase.md` with a generated `## Slices` block (markers must be alone on their line; absent = no-op), and `finish-slice` takes `--outcome "one line"` stored in `slice.json` (omitted = warning, never an error). (P18.S1)
- operations.md: `validate` now warns (never errors, and never on a `done` phase) when a notebook exceeds `PHASE_MD_BUDGET` = 200 lines / 16 KB, and on a case-drifted `## Doc Impact` heading; `finish-slice` prints `phase.md: <lines> lines / <bytes> bytes (budget 200 / 16384)`; `works/backlog.md` and `works/deferred.md` no longer carry a `- Rebuilt at:` line, so repeated `next` calls leave them byte-identical. (P18.S2)
- operations.md: the runbook's read-and-write protocol — executors read just in time (`plan.md` → `phase.md` → `intent.md` only when unsure → `phase.json` → the `docs/current/` **sections** the plan names, never the whole set and never `docs/index.json`), `result.md` leads with the verdict block, `phase.md` is **edited** under the 200-line / 16 KB budget (Decisions replace superseded lines; Doc impact and Operator Questions append-only; Notes consumed; `## Now` rewritten; the `## Slices` marker block never hand-edited), drivers run `finish-slice --outcome` and no longer re-read `works/backlog.md` per slice, and the review cross-checks `phase.md` against every `result.md`. (P18.S3)
- operations.md: the contract's read order is now just-in-time and three steps (`works/state.json` + `next` → the active phase folder, `intent.md` plus the bounded `phase.md` → only the `docs/current/` **sections** the work touches, never the whole set and never `docs/index.json`), and `CLAUDE.md` states `phase.md` as bounded state **edited** under `PHASE_MD_BUDGET` with the generated `## Slices` block off-limits, `result.md` as the verdict-first per-slice log, and `finish-slice --outcome`; both READMEs mirror it. (P18.S4)
- decisions.md: an ADR for the review to write — the phase notebook is bounded *rewritten state* rather than an append-only log (the audience split with `result.md`, warn-never-error budget, restorability through git + `result.md` by path), and **no prompt-cache setting changed** (`intent.md` clarification 2: Claude Code already caches automatically and file reads land as messages, not prefix, so size — not churn — was the lever). (P18.S4)
- operations.md: workspace v35 released (`installer/main.py:38`, `## v35` in `CHANGELOG.md`); the "Building and releasing the installer" section's release rule is prose, not a version list, so nothing there needs a new line. (P18.S5)
