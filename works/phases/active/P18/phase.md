## Decisions

- **The installer rebuild rides every slice that touches an embedded file** (`scripts/workflow.py`, `.claude/*`, `works/templates/*`, `CLAUDE.md`): S1–S4 each run `python3 installer/build.py` before returning, because the tracked pre-commit hook runs `installer/build.py --check` on every commit. S5 owns only the version bump + CHANGELOG.
- **A new embedded file must be registered in four places** or the build/tests fail: `FIXED_LIVE_FILES` (`installer/build.py`), `MANAGED_FILES` (`installer/main.py`), the emitted fresh-install writer (`installer/main.py`), and the hand-maintained `DUAL_FIXED` manifest in `tests/retrofit_smoke.sh` — Test 6 parses `FIXED_LIVE_FILES` by AST and fails when the manifest drifts.
- **`works/templates/` is machinery in the update policy**, so adopters get the new template on `--update` while every existing `works/phases/**/phase.md` is preserved. That is why the marker-less path is a **silent no-op, never a migration**.
- **A marker counts only when it is alone on its line** (P18.S1): the decomposition table above quotes the literals in prose, and the first implementation spliced the generated table into that table cell. Notebooks may discuss the markers freely.
- **The `## Slices` writer writes only on change** — `write_text()` always rewrites (atomic replace, no unchanged-content skip), so a read → splice → compare guard is what keeps `next`/`rebuild` from dirtying every notebook.
- **`phase.md` is not in `GENERATED_FILES`.** Only the marker block is generated; `parallel-merge-finish`'s "resolve by taking either side" advice must never apply to the whole notebook. Correct guidance for a conflict *inside* the block: re-run `rebuild` (S3 adds that line to the `parallel-phase` skill).
- **Scope of the `- Rebuilt at:` removal is the two markdown dashboards only** — `index.json.last_rebuilt_at` and `state.json.updated_at` stay (operator-confirmed, `intent.md` part 3). Dropping it leaves `rebuild_deferred_dashboard(groups, rebuilt_at)`'s second argument unused (callers: `rebuild_index_and_state`, `cmd_deferred`): clean it up or keep it deliberately.
- **Both new `validate` checks are warnings, never errors** (`intent.md` clarification 4): `validate()` keeps `warnings` and `errors` in separate lists, prints warnings first, and still exits 0 with warnings.
- **Gate:** `accept-gate P18 --waive` (workspace machinery, no operator-visible product surface). This repo has no `## Operator Runtime` section and needs none — do not add one in this phase.
- **P18's own `phase.md` is the migration test bed:** S1 migrated it in place (this file); S2–S5 edit it under the new rules, and the review measures the result.
