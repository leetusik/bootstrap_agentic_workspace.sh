## Notes

Findings from the orchestrator's 2026-10-11/12 lookups, for `DECOMP` (sources: Anthropic's Haiku 5.5 announcement; Anthropic's *Optimizing for cost and intelligence* and *Effort* docs; the Claude Code sub-agents and model-config docs; the `claude-api` skill's Opus 5.5 / Sonnet 5.5 / Haiku 5.5 migration sections):

- **Why one notch below `flex` on every Opus row.** Anthropic's own SWE-bench Pro runs on Opus 5.5, relative to `high`: `xhigh` +1.4 points at **2.5x the cost**; `medium` −2.5 points at ~70% of the cost; `low` −8 points at ~1/3 of the cost (87.4% at $0.12 per solved task). `high` everywhere: 95.3% at $0.29/task; `medium` start: ~97% at $0.24; `low` with failures re-run at `high`: ~97% at $0.17 — "most of the lift comes from the second attempt", which is this workspace's escalation ladder. Opus 5.5 at `medium` (92.8%) matched Fable 5.1 at its default (92.3%) within noise. Anthropic's starting point for agent workloads: Opus 5.5 at `medium`. Opus 5.5 thinks more per turn than Opus 5 at `xhigh`/`max`, so turns run longer there.
- **Why `research` at `medium`.** Research and knowledge-work curves are nearly flat: `medium` matched the default's accuracy at 70–87% of its cost; `low` gave up 1–3 points for a third to a half off and ran far faster (4.5 vs 7.9 minutes per problem on DeepWideSearch).
- **Why Sonnet at `high` on the mid row.** Anthropic's Sonnet 5.5 guidance: `medium` for well-specified agentic coding, `high` "for harder or longer" tasks; at `low` it sometimes reports a change done without a real check. The executor's run is long (plan, notebook, code, validation, `result.md`, notebook edit) → `high`; `medium` is the first measured step-down. No published Sonnet 5.5 effort curve exists, hence the instrument. Published precedent for the alternative: the frontier model at `low` beat the smaller model per solved task (Fable 5.1 `low` 88.6% at $0.54 vs Sonnet 5 77.4% at $0.84 on SWE-bench Pro) — so `opus` @ `low` is the other candidate for the mid row.
- **Why Haiku at `high`.** Haiku 5.5: `claude-haiku-5-5`; $0.10 / $0.50 per MTok in/out up to a 100K-token prompt, $0.50 / $2.50 above; 1M context, 128K output (Haiku 4.5: 200K, which would have broken on the 400 KB `phase.md` budget). Terminal-Bench 4.0 **39.2%** vs Sonnet 5.5 70.6% (Haiku 4.5: 0%); FrontierCode 1.1 46.4% vs 52.1%. Anthropic: not recommended for complex agentic coding; positioned as a subagent under Opus/Sonnet for lookups, extraction, summaries and compaction; the fastest model Anthropic ships at standard speed. Documented failure modes: early stop in long agent prompts at `low`; skipped verification at `low`/`medium`; strict instruction following needs `high`. Thinking on by default; no server-side refusal fallback. Advisor data: Haiku/Sonnet executors never consulted an Opus advisor — the ladder, not an advisor, is the right lift here.
- **Why reads may be delegated and writes may not.** Anthropic's orchestrator measurements: delegation pays only when bulky, independent work would flood the deciding model's context; on a dependent chain the coordinator's model alone at lower effort won every time. `result.md` and `phase.md` are judgment outputs from the executor's own context — a handoff costs what writing them costs. Reads are the flood case here: the notebook budget is 400 KB, the decisions log is 275 KB, `validate` warns `oversized_doc_sections=8`, and every token an executor pulls in is re-read (cached) on every later turn — a 70K-token read costs an Opus executor ~$0.28 once plus ~$1.40 in cache reads over 100 turns, against ~$0.007 for a Haiku Explore summary and 1–2K tokens carried.
- **Harness facts that make the design possible (Claude Code 2.1.296):** since **2.1.292** the Agent tool takes a per-invocation `effort` beside the long-standing `model`; both override the agent file's frontmatter and persist on resume (decision v0013's "effort is frozen at spawn" premise is gone). The Agent tool's `effort` field is to be set only when a skill or the contract instructs it, so the rule must live in the skill text. **Nesting is allowed**: a subagent whose `tools` list includes `Agent` may spawn subagents up to three layers below the main conversation (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`); omit `Agent` to forbid it — the executors omit it today. **A project agent named `Explore` overrides the built-in and keeps its own `model`**; the built-in runs on the main conversation's model, on the Opus alias when the main is Fable (subscription); Explore and Plan do not load `CLAUDE.md`. Subagents see none of the parent's context and return only their final report. **Verify at DECOMP:** `CLAUDE_CODE_EFFORT_LEVEL` outranks frontmatter effort; check whether it also outranks the per-invocation value (none is set on this machine today).
- **Aliases on the Anthropic API (2.1.296):** `haiku` → Haiku 5.5, `sonnet` → Sonnet 5.5, `opus` → Opus 5.5. On Bedrock / Vertex / Foundry `haiku` → Haiku 4.5 (hence opt-in for adopters). Claude Code effort default is `medium` on Opus 5.5, Sonnet 5.5 and Haiku 5.5 — every row must set effort explicitly.
- **ocx / Kiro (checked 2026-10-11):** Kiro's catalog has no Haiku 5.5 and no Sonnet 5.5; the ocx model map covers `claude-sonnet-5` and `claude-haiku-4-5` only. Never map `claude-haiku-5-5` onto Kiro's Haiku 4.5. Detect the proxy at dispatch time (the session's `ANTHROPIC_BASE_URL` points at 127.0.0.1:10100) and fall back to the mid row's model; pass `sonnet` to Explore there.
- **History baseline:** 29 of 181 recorded slices were mid-eligible (risk `low`, kind implementation/fix/docs/qa); 12 were docs consolidations. Sonnet escalated from mid once. `executors.toml`'s "haiku is deliberately never an executor tier" (v46) and the engine comment above `EXECUTOR_PRESETS` were housekeeping on Haiku 4.5 assumptions and are superseded by this phase; the retired `low` tier (v23) is **not** reintroduced — rows, not a third tier. The presets arrived in v29 and were cut to Claude-only in v31; the `economy`/`flex` words appear in `scripts/workflow.py`, `executors.toml`, `tests/retrofit_smoke.sh`, the two `do-*` skills, the `executor-mode` skill, the installer and the operations doc.
- **Economics with the ladder:** a Haiku failure escalates to Opus, so the cheap route beats Sonnet-first on cost once Haiku finishes roughly half its slices; the real risk is a false `done` caught only at the phase review, which `high` effort and the review's re-validation guard.
