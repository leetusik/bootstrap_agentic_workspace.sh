## The dispatch protocol the skills must state (same words in both `do-*` skills)

1. **Resolve.** After `plan.md` is written (and after `start-slice`), run `python3 scripts/workflow.py executor-route <slice_id>` — add `--retry` on a second attempt (escalation, a failed/empty mid return) — and `python3 scripts/workflow.py executor-route --explore`. The decision is the engine's: kind first, then risk, then attempt. **Bump up, never down:** when the plan you wrote hits a named trigger on a slice rated `low`, set `risk` to `high` in its `slice.json` (that one field; `python3 scripts/workflow.py rebuild` regenerates the table), say why in `plan.md`, and resolve again. Never lower a rating.
2. **Pin.** Append a final `## Dispatch` section to the slice's `plan.md` holding the slice form's lines verbatim (`route=` … `attribution=`) plus two lines from the `--explore` form renamed `explore_model=<model>` and `explore_effort=<effort>` — the executor reads its `model`/`effort` from there (D6) and the lookup model for `Explore` (D9). On a retry, the new lines go under the `## Escalation: mid → high` section instead.
3. **Dispatch.** Agent tool, background task (as today): `subagent_type` = the `subagent_type=` line; pass `model` only when `pass_model=yes` (its value is the `model=` line, one of the Agent tool's aliases); pass `effort` only when `pass_effort=yes`. A `fallback=` line is informational (`model=` already carries the fallen-back model). Relay every `warning=` line to the operator in your report: it means the per-dispatch value will not take effect on this machine. The prompt stays what it is today: slice id, folder, repo root.
4. **Record.** After the completion notification, run `record-dispatch` exactly as the S2 note spells it: `python3 scripts/workflow.py record-dispatch <slice_id> --route <route=> --tier <tier=> --model <model=> --effort <effort=> --verdict <done|escalate|needs_operator|blocked|failed> --attempt <attempt=> --agent <subagent_type=> --duration-ms <duration_ms> --tokens <subagent_tokens> --tool-uses <tool_uses>` — the three numbers from the notification's `<usage>` block (H5); a failed or empty return is `--verdict failed`. Record before `finish-slice`, so the record rides in the slice's commit. The drafter span records with `--agent design-drafter` and the `--drafter` form's route (`high`); the mockup span records like any slice.
5. **Attribute.** The slice commit's trailer is `Co-Authored-By: <attribution> <noreply@anthropic.com>` where `<attribution>` is the `attribution=` line of the dispatch that produced the work — equivalently the name for the `model:` the verdict block records (D7). A slice done by two attempts is attributed to the model that completed it. Commits that carry only the orchestrator's own work (phase creation, a gate declaration alone, a verdict record) are attributed to the session's model as today. Never carry over another session's trailer.
6. **Explore for lookups.** The orchestrator's planning research and the idle-window preparation use the project `Explore` agent (`subagent_type: Explore`) with the `--explore` form's `model`/`effort` (haiku @ high; the engine prints `sonnet` under a loopback proxy); **upgrade per call** — pass `model: sonnet` or `model: opus` — for a lookup that needs judgment (why, a trade-off, an audit). Explore locates and summarizes; it never decides, and its brief is advisory input to your plan, never a plan. `Plan`-type agents and inline reads stay available as today.
