# Plan — P32.DECOMP: decompose "One executor route table: dispatch-time model and effort, no presets, Haiku cheap route"

## Context

P32 replaces the `economy` / `flex` executor presets with one engine-owned **route table** — a (model, effort) row per route, overridable per row in `executors.toml` — and moves model and effort selection to **dispatch time**: the orchestrator passes `model` and `effort` on every Agent-tool dispatch from the resolved table, and the tier agent files' frontmatter stays synced from the same table as the fallback only. It adds the **cheap route** (docs/qa rated `low` → `haiku @ high`, on in this repo, opt-in for adopters), a project **`Explore`** agent on Haiku for read-only lookups (the orchestrator's planning research, and executors' bulky reads through a new `Agent` tool), and the **instrument**: a machine-readable record of every dispatch plus a summary by route, so the table is tuned from this workspace's own runs. Ships as workspace v53. The operator's verbatim words, the confirmed intent, the shipped table and the research notes behind every row are in `works/phases/active/P32/intent.md` — read it whole before cutting.

This slice is the decomposition: it fixes the design decisions below (recorded in `phase.md` `## Decisions`), cuts the middle slices as **bare folders** (never pre-filling a `plan.md`), rates each one deliberately, and leaves `phase.md` bounded and complete for S1. It writes no product code.

## Decisions to fix (record each in `## Decisions`)

**D1 — The route table: five rows, engine defaults, per-row overrides.** `EXECUTOR_ROUTES` replaces `EXECUTOR_PRESETS` / `DEFAULT_EXECUTOR_MODE`:

| Row | Tier (agent file) | Default | Serves |
|---|---|---|---|
| `high` | `slice-executor-high` | `opus @ high` | `review`, `decomposition` and `co-work` (the mockup span) by kind; any slice whose `risk` is not exactly `low`; every **second attempt** (escalation, failed/empty mid return, a `fix` of mid's work); `design-drafter` follows this row |
| `research` | `slice-executor-high` | `opus @ medium` | `research` by kind |
| `mid` | `slice-executor-mid` | `sonnet @ high` | `implementation` / `fix` rated `low` |
| `cheap` | `slice-executor-mid` | **inherits the `mid` row** (model and effort) | `docs` / `qa` rated `low` — the cheap route; this repo overrides it to `haiku @ high` |
| `explore` | `Explore` (new agent file) | `haiku @ high` | the read-only lookup agent; not a slice route |

Four rows, not a per-kind row for `review` and `decomposition`: they share the `high` row's values, an adopter's existing `[claude.high]` override keeps its full old meaning (minus `research`), and the dispatch record carries kind and risk, so the summary can still split them. Rows, never a third tier: `cheap` dispatches to the **mid agent file** with `model`/`effort` passed per call; the verdict block says `tier: mid` and `model: haiku`.

**D2 — `executors.toml` schema and migration.** Tables are `[claude.<row>]` for the five rows, keys `model` / `effort`, double-quoted; `[claude.mid]` and `[claude.high]` keep their names so existing overrides keep working. The top-level `mode = "…"` line is **rejected with a named v53 migration message** (the `[claude.low]` / `[codex.*]` precedent): "the economy/flex presets were retired in workspace v53 — delete this line; the route table replaces them (flex was xhigh on both tiers: set effort = "xhigh" under [claude.mid] and [claude.high] to keep it); run `executor-route` to see the resolved table". `effort = ""` still omits the effort line (and the per-dispatch effort). A model that is not an Agent-tool alias (`opus|sonnet|haiku|fable`) is accepted only on rows that own an agent file (`mid`, `high`, `explore`), where sync-agents writes it into the frontmatter and the dispatch omits `model` so the file's value applies; on `research` and `cheap` — rows with no file of their own — a non-alias model is a line-numbered error, because the dispatch could not honour it (H6).

**D3 — The cheap route is on here and seeded commented-out.** The live `executors.toml` sets `[claude.cheap] model = "haiku"`, `effort = "high"` inside a marked block (`# cheap-route: begin` … `# cheap-route: end`); `installer/build.py` derives the adopter seed from the live file by commenting out the non-comment lines of that block (deterministic, single source, no second copy of the header). The header explains: the `haiku` alias is Haiku 5.5 on the Anthropic API and **Haiku 4.5 on Bedrock, Vertex and Foundry**, hence opt-in; the engine default for `cheap` is the `mid` row, so an unconfigured workspace routes docs/qa exactly as today. The "haiku is deliberately never an executor tier" line and the engine comment above the presets are removed as superseded.

**D4 — `executor-route`: the deterministic, engine-printed routing decision.** New command; `executor-mode` and its skill are retired. Bare: prints the resolved table (row, tier, model, effort, source `default` / `executors.toml`), the agent-file sync state, and the environment notes below. `executor-route <slice_id> [--retry]` prints one key=value line to dispatch from: `slice= kind= risk= attempt= route= tier= subagent_type= model= effort= attribution=` — `--retry` means a second attempt and always resolves to `high`. `executor-route --drafter` (the `high` row for `design-drafter`) and `executor-route --explore` (the `explore` row) print the same shape. The rule is **kind first, then risk, then attempt**, exactly D1; the orchestrator may bump a slice up (`--retry`, or a `high` rating), never down. Environment notes (H1–H3): a **loopback `ANTHROPIC_BASE_URL`** (ocx's sidecar is `127.0.0.1:10100`; Kiro serves no Haiku 5.5) makes `cheap` fall back to the `mid` row's model and `explore` to `sonnet`, printed as `fallback=`; `CLAUDE_CODE_EFFORT_LEVEL` set → `warning:` it outranks every per-dispatch effort; `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` set → `warning:` it overrides every model. `new-slice` / `promote-deferred` `--risk` help text and the `SLICE_KINDS` comment are reworded for routes.

**D5 — The instrument: `record-dispatch` and `dispatch-summary`.** `record-dispatch <slice_id> --route <row> --model <m> --effort <e> --verdict <done|escalate|needs_operator|blocked|failed> [--attempt N] [--tier mid|high] [--agent <name>] [--duration-ms N] [--tokens N] [--tool-uses N]` appends an `executor_dispatched` event to `works/events.jsonl` (already union-merged, stamped and managed; no new file) carrying slice, phase, kind, risk and the given fields. `dispatch-summary [--phase P]` reads it back by route: dispatches, verdict counts, retries, mean and total duration, total tokens, and the per `model @ effort` split. The numbers come from the Agent completion notification, which reports `subagent_tokens`, `tool_uses` and `duration_ms` (H5). The orchestrator runs the record after every executor return (drafter and mockup spans included); it is a plain record of what was dispatched, never a validation of the route.

**D6 — Where the executor learns its model.** A subagent cannot introspect its model, so the orchestrator appends the `executor-route` line to the slice's `plan.md` as a final `## Dispatch` section before dispatching (and again under `## Escalation: mid → high` on a retry); the executor copies `model` and `effort` from it into its verdict block beside `tier` (`- tier:`, `- model:`, `- effort:`). The high-tier executor on a review reads them to rate fix slices as before (`tier: mid` → `high`).

**D7 — Commit attribution follows the recorded model.** The engine owns one alias → name map (`opus` → Claude Opus 5.5, `sonnet` → Claude Sonnet 5.5, `haiku` → Claude Haiku 5.5, `fable` → Claude Fable 5.1; anything else verbatim), printed as `attribution=` by `executor-route`; the slice commit's `Co-Authored-By` names the model the verdict block records, never the tier's old fixed name. When Anthropic moves an alias, one constant and a CHANGELOG line change.

**D8 — The `Explore` agent.** `.claude/agents/Explore.md`: `name: Explore`, `tools: Read, Grep, Glob`, `model: haiku`, `effort: high`, `omitClaudeMd: true` (the built-in skips `CLAUDE.md`; a custom agent loads it unless told not to — H4), body: locate and summarize, return a compact brief with paths, never judge or recommend, never write. It overrides the built-in and keeps its own `model` (H4); callers still pass `model` and `effort` per call from `executor-route --explore`, and **upgrade per call** to `sonnet` or `opus` through the Agent tool's `model` for a lookup that needs judgment (why, tradeoffs, an audit). It is managed like the other agent files (`sync-agents` writes its frontmatter from the `explore` row; installer `FIXED_LIVE_FILES`, `MANAGED_FILES`, `NESTED_AGENTS`). In a nested install whose host already has an `Explore.md` the installer renames ours as it renames any clashing agent; the renamed copy no longer overrides the built-in but still runs on Haiku — accepted, noted in the CHANGELOG.

**D9 — Executors get `Agent`, for reads only.** Both tier files add `Agent` to `tools` and one shared paragraph: delegate **bulky read-only lookups whose output you do not need in full** (a doc section, a search across the code, a summary of a long file) to `Explore` with the model and effort the plan's `## Dispatch` section names for lookups (haiku @ high; sonnet under the proxy), upgrade to `sonnet`/`opus` for judgment, and **never** delegate `result.md`, `phase.md` edits, code changes, validation or the verdict — those stay in your own context. The cheap route's own Haiku executor is told it gains nothing from delegating and reads inline. The two bodies stay byte-identical below the frontmatter (the smoke test's drift detector). Nesting depth stays the harness default of 3; executors sit at depth 1.

**D10 — What stays fixed.** Two tiers and their licences; kind-first routing; `risk` as the operator's cost lever; the one-step `mid → high` ladder and "never back to mid"; `sync-agents` and its drift warning (`validate` keeps warning, never erroring); the design subagent following the top row; `--risk` unvalidated. **D11 — The orchestrator's effort stays at the session level.** Nothing in P32 sets it; the published finding (`max` buys little over `high` for planning-shaped work) is a Doc impact line for the operations doc, written by the skills slice.

## Harness facts to carry into `## Notes for later slices` (verified 2026-10-12 against code.claude.com/docs; Claude Code 2.1.296)

- **H1 — Effort precedence:** `CLAUDE_CODE_EFFORT_LEVEL` > per-invocation Agent-tool `effort` > frontmatter `effort` > `--effort` / `/effort` > saved settings > model default. The env var outranks the table, so `executor-route` warns when it is set (none is set on this machine). The model default differs by model (the docs say `medium` for Haiku 5.5, `high` for most others), which is why every row sets effort explicitly.
- **H2 — Model precedence:** per-invocation `model` > frontmatter `model:` (`inherit` = the main model) > `CLAUDE_CODE_SUBAGENT_MODEL` > the main model; `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` reverses it and makes every `model:` moot → warn.
- **H3 — Aliases:** `haiku` → Haiku 5.5 on the Anthropic API, Haiku 4.5 on Bedrock and Vertex (Foundry likewise); aliases move over time, so a full id is the way to pin one.
- **H4 — Explore override:** a project `.claude/agents/Explore.md` overrides the built-in and keeps its own `model`; whether it keeps `effort` is undocumented (pass it per call too); the built-in skips `CLAUDE.md`, a custom agent needs `omitClaudeMd: true` (2.1.271+) to do the same. Nesting: a subagent whose `tools` lists `Agent` may spawn up to three layers below the main conversation (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`, settings `env`).
- **H5 — The completion notification** of a background Agent carries `<usage><subagent_tokens>…</subagent_tokens><tool_uses>…</tool_uses><duration_ms>…</duration_ms></usage>` — the record's three measured fields.
- **H6 — The Agent tool's `model` parameter is an enum** (`sonnet | opus | haiku | fable`); a full model id or `inherit` cannot be passed per dispatch (D2's alias rule). Its `effort` enum is `low | medium | high | xhigh | max`.
