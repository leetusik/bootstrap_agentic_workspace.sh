# Phase P32: One executor route table: dispatch-time model and effort, no presets, Haiku cheap route

_Intent: see [intent.md](intent.md)._

## Objective

Replace the economy/flex presets with one engine-owned executor route table and move model and effort selection to dispatch time. The orchestrator passes model and effort on every executor dispatch from the resolved table (engine defaults overlaid by per-row overrides in executors.toml), the two tier agent files' frontmatter staying synced as the fallback only. Shipped rows: review, decomposition, risk-high slices and every second attempt -> opus @ high; research -> opus @ medium; implementation and fix rated low -> sonnet @ high; docs and qa rated low -> haiku @ high (the cheap route: on in this repo, seeded commented-out for adopters, falling back to the mid row's model under ocx claude); design-drafter follows the review row. A project Explore agent runs read-only lookups on haiku @ high, upgraded per call to sonnet or opus for judgment; executors on both tiers get the Agent tool for such read-only lookups only, never for result.md, phase.md, code or validation. Every dispatch leaves a machine-readable record (slice, tier, model, effort, duration, tokens, verdict) through an engine command, with a summary by route, so the table is tuned from this workspace's own runs. Executors record model and effort beside tier in the verdict block and commit attribution follows the recorded model. The orchestrator's effort stays at the session level. Ships as workspace v53.

## Decisions

- **D1 — One route table, five rows (P32.DECOMP).** `EXECUTOR_ROUTES` replaces `EXECUTOR_PRESETS` / `DEFAULT_EXECUTOR_MODE`. Rows (row → agent file, default, serves): `high` → `slice-executor-high`, `opus @ high`: `review`, `decomposition`, the `co-work` mockup span by kind, any `risk` not exactly `low`, every second attempt (escalation, failed/empty mid return, a `fix` of mid's work); `design-drafter` follows it. `research` → `slice-executor-high`, `opus @ medium`: `research` by kind. `mid` → `slice-executor-mid`, `sonnet @ high`: `implementation` / `fix` rated `low`. `cheap` → `slice-executor-mid`, **inherits the `mid` row** unless overridden: `docs` / `qa` rated `low` (this repo: `haiku @ high`). `explore` → `Explore`, `haiku @ high`: read-only lookups, not a slice route. Rows, never a third tier: `cheap` runs the mid file with `model`/`effort` passed per call (verdict `tier: mid`, `model: haiku`). Review and decomposition share `high` (an old `[claude.high]` override keeps its meaning minus `research`); the record's kind/risk splits them in the summary.
- **D2 — `executors.toml` schema (P32.DECOMP).** `[claude.<row>]` for the five rows, keys `model` / `effort`, double-quoted; `[claude.mid]` / `[claude.high]` keep their names. A top-level `mode = "…"` is rejected with a named v53 migration message (presets retired; flex = `effort = "xhigh"` under `[claude.mid]` and `[claude.high]`; run `executor-route`), on the `[claude.low]` / `[codex.*]` precedent. `effort = ""` omits the effort line and the per-dispatch effort. A model outside the Agent-tool aliases (`opus|sonnet|haiku|fable`) is accepted only on rows owning an agent file (`mid`, `high`, `explore`: written into the frontmatter, and the dispatch omits `model`); on `research` / `cheap` it is a line-numbered error (H6). `effort` must be one of `low|medium|high|xhigh|max` or `""`, and an unknown `[claude.X]` is `unknown route X` — both line-numbered (P32.S1).
- **D3 — Cheap route on here, commented-out for adopters (P32.DECOMP).** The live `executors.toml` sets `[claude.cheap] model = "haiku"`, `effort = "high"` between `# cheap-route: begin` / `# cheap-route: end`; `installer/build.py` derives the adopter seed by commenting out that block's non-comment lines (single source). The header says why it is opt-in (`haiku` = Haiku 4.5 on Bedrock / Vertex / Foundry) and that an unset `cheap` is the `mid` row. The v46 "haiku is deliberately never an executor tier" line and the engine comment above the presets go.
- **D4 — `executor-route`, the engine-printed routing decision (P32.DECOMP; output settled by P32.S1).** New command; `executor-mode` (command and skill) retired. Every form prints **one `key=value` per line** and writes nothing. Bare: a `route  tier  model  effort  source` table (five rows, `explore`'s tier `-`; source `default` / `executors.toml` / `mid row` / `model X / effort Y`), `agent files: in sync` or `agent files: out of sync: … (run: … sync-agents)`, then `proxy=none` or `proxy=<url> (loopback)` + `fallback=` lines. `executor-route <slice_id> [--retry]`: `slice= phase= kind= risk= attempt= route= reason= tier= subagent_type= model= pass_model= effort= pass_effort= attribution=` in that order; `--drafter` / `--explore`: `agent= route= tier= subagent_type=` then `model=` … `attribution=`. Rule (`slice_route`): `--retry` → `high` (`reason=second attempt`); kind `review` / `decomposition` / `co-work` → `high`; `research` → `research`; risk not exactly `low` → `high`; `implementation` / `fix` → `mid`; `docs` / `qa` → `cheap`; anything else → `high`. `pass_model=no` when the model is not an alias (dispatch omits `model`; the frontmatter carries it), `pass_effort=no` when effort is `""` (omit `effort`). Env: loopback `ANTHROPIC_BASE_URL` (127.0.0.1 / localhost / ::1, scheme optional) → `cheap` takes the `mid` model and `explore` `sonnet`, already reflected in `model=` / `attribution=`, plus `fallback=<row> model <m> -> <m2> (…)` only when the model changes; `CLAUDE_CODE_EFFORT_LEVEL` set → `warning=CLAUDE_CODE_EFFORT_LEVEL=<v> is set and outranks every per-dispatch effort …`; `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` truthy → `warning=CLAUDE_CODE_SUBAGENT_MODEL_FORCE=<v> is set and overrides every model …`. Misuse exits 1: two of `<slice_id>` / `--drafter` / `--explore` (`… are mutually exclusive`), `--retry` without a slice (`--retry needs a <slice_id>`); an unknown slice is `slice not found:`. The `--risk` help (`new-slice`, `promote-deferred`) and the `SLICE_KINDS` comment are reworded for routes.
- **D5 — The instrument (P32.DECOMP).** `record-dispatch <slice_id> --route <row> --model <m> --effort <e> --verdict <done|escalate|needs_operator|blocked|failed> [--attempt N] [--tier mid|high] [--agent <name>] [--duration-ms N] [--tokens N] [--tool-uses N]` appends an `executor_dispatched` event (slice, phase, kind, risk + the fields) to `works/events.jsonl` — no new file. `dispatch-summary [--phase P] [--slice S] [--json]` reads it back (read-only) by route, by `model @ effort` and by kind: dispatches, verdict counts, retries (any `attempt` ≥ 2, so a same-tier re-dispatch after a `blocked` counts too), mean/total duration, total tokens; its header is one `key=value` per line (`records=` / `phases=` / `since=` / `until=`), `--slice` lists the slice's records one per line, malformed log lines are skipped and counted (`skipped_lines`), and `--phase` is accepted when the phase is active, archived or has records, `--slice` when the slice is active or has records, else exit 1 (output settled by P32.S2). The record also carries `attribution`, `tier` defaulting to the route's tier, `agent` to the installed agent, and an optional `--note`. Numbers come from the Agent completion notification (H5); the orchestrator records every executor return (drafter and mockup spans included) — a record, never a route validation.
