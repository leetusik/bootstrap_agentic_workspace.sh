- **Reading (a), ocx + `DesignSync` (P25.S1): strongly indicated, and the reading is corrected.**
  - `DesignSync` is a **built-in** Claude Code tool (not MCP). It talks to `api.anthropic.com` directly, not through `ANTHROPIC_BASE_URL`.
  - A stock `ocx claude` session (the operator's `authMode: proxy`) displaces the claude.ai login, so `DesignSync` hits `needs_design_login`.
  - Claude Code's `/design-login` is built for API-key and provider-token sessions and should make it work. That is **unverified live**: it needs the operator's claude.ai account.
  - Either way Claude Design needs a paid claude.ai plan.
  - **Verified:** "main-thread only" means Claude Code drops built-ins such as `DesignSync` from **background** subagents. Background subagents keep **every MCP tool + Bash**, so MCP- or file-driven candidates pass criterion 3 structurally.
- **Reading (b), Claude Design's intended use (P25.S1): verified.**
  - The native flow designs in Claude Design, then *pushes* a handoff bundle into Claude Code. Design systems are org-level artifacts.
  - Ours *pulls* rounds back with `DesignSync`. That tool's own description restricts it to the operator-started `/design-sync` push of a code component library, so our read-back and the SIGNOFF regroup write are outside its stated purpose.
  - A native agent-side `ClaudeDesign` tool exists behind flag `tengu_omelette_fouet` (default off). It is also a built-in.
- **Shortlist for S2 (P25.S1)**, as passes of the 5 criteria in `intent.md` (C1 both harnesses, C2 no SaaS, C3 subagent-drivable, C4 frames surface, C5 memory):
  1. **Repo-native static frames board**: agent-written numbered HTML cards, a generated board index served locally, Aside read-back. Passes all 5, zero deps; the surface is ours to build.
  2. **Storybook + `@storybook/addon-mcp`** (Ladle/Histoire as framework-limited variants). Passes all 5 and is mature; adds a toolchain to each product repo.
  3. **Self-hosted Penpot + official MCP**. A real design canvas; C3 is **unclear** because the MCP plugin needs a live browser tab; heavy infra; memory lives outside the repo.
  4. **Self-hosted Doop**. Agent frames, screenshots and comments over MCP; very young (created 2026-08-22); C5 unclear.
  - **Screened out:** pen.dev (mandatory login), OpenDesign (read-only MCP, inverted control), Open CoDesign, Onlook, Superdesign, and Figma/SaaS canvases (C2/C3); Excalidraw, tldraw and draw.io (diagram-grade, C4).
- **Ranked top 3 (P25.S2)**, evidence in `slices/P25.S2/result.md` §1–§3:
  1. **Repo-native frames board.** Passes C1–C5 with zero deps and zero MCP cost. The scratch prototype verified R3 (grouped, numbered, viewport frames, round address), R4 (contract check + headless per-card screenshots) and R7 (a line-1 regroup, `git diff` 1/1 per card, idempotent). The memory is the repo. Costs: we build and own the board (~150 lines), and there are no element comments or direct edits. Feedback comes back as per-card notes → "copy as markdown" (verified) plus the operator's words at their return.
  2. **Storybook 10.6 + addon-mcp.** Passes all five, mature, renders real components for JS component-library products. The regroup is a `title`-only diff, and URLs stay stable **only with an explicit meta `id`** (verified). An MDX round board works, but at docs width. Costs: 4 devDeps / ~100 MB / 212 packages per product repo, and ESM config. On `html-vite` only the 4-tool dev toolset exists (~3.6k tokens/turn under ocx if registered session-wide).
  3. **Self-hosted Penpot 2.18 + built-in MCP.** The only real canvas: direct edits, comments, token sets, live multiplayer (verified). **C3 passes conditionally**: MCP drives the file only while a tab holds the user's connection. An agent-held headless tab works (verified), but it becomes a sidecar to run. Hazards: agent and operator must be separate Penpot users (a same-user operator tab silently takes over when the agent tab closes), and the plugin API modifies only the active page. Costs: ~7.5 GB of images, ~1.0–1.4 GB RAM, memory in the instance DB, and a per-round export for R5. PNG export was unverified (the exporter was OOM-killed under the probe's cap).
  - **Doop dropped** (docs and source only): five weeks old, 86% of commits by one author, memory in its DB with no tokens, MCP OAuth-only (subagent reuse strongly indicated, unverified), no published image, binds all interfaces.
  - **MCP cost lever for adoption:** define the server inline in a drafting subagent's `mcpServers:`. The main thread then never inlines its schemas, which matters under ocx.
- **Claude Design (P25.S2): retire the `DesignSync` read-back + regroup loop.** Keep Claude Design only as an optional, operator-driven **import of its native handoff bundle**, filed as-is into the replacement's record. The rest of the loop runs on the replacement.
  - Not recommended: keeping the current pull loop as an opt-in behind `/design-login`. It is main-thread only, paid, off-label for `DesignSync`, and it would double the skill.
  - Unverified: `/design-login` under ocx, whether the bundle push reaches an `ocx claude` session, and how a bundle maps onto numbered card paths.
- **`frontend-design` (P25.S2):** for the drafter only, on HTML-authored options (the board, Storybook story-local markup), and only on rounds that set a new visual direction. Never on rounds extending an established `tokens.css` + library. Barely relevant to Penpot.
