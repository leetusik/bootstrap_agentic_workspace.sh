# Phase P29: Nested install by default

_Intent: see [intent.md](intent.md)._

## Objective

Make the nested personal install the installer's default layout everywhere (existing repos and fresh dirs, which get git init + nested workflow/); the at-root layout only on --at-root (or --into-existing); --update auto-detects the installed layout from its marker so /update-workspace needs no --nested; existing at-root installs keep updating at-root with no migration; ship as v50.

**Decisions S1 must hold.**
1. **Mode resolution: one function at the top of `main.py`, before `HOST, ROOT` are set** (today `NESTED` is read from env at import, ~L52). The wrapper exports `AT_ROOT`; `NESTED` is set only by an explicit `--nested`. Order: `--into-existing` or `--at-root` → at-root. `--update` → **detect**: `<target>/workflow/.agentic-nested.json` → nested; at-root workspace (`scripts/workflow.py` + `works/`) → at-root; both → refuse as ambiguous, naming both; neither → today's "no agentic workspace found". An explicit `--nested`/`--at-root` that **contradicts** the detected layout refuses in one line; a matching one is a no-op (keeps v49's `--update --nested` text working). Otherwise (fresh install) → **nested**.
2. **Wrapper conflicts:** `--at-root` + `--nested` → refuse. `--nested` + `--into-existing` → refuse (unchanged). `--force-empty-ok` without `--at-root` (or `--into-existing`, unchanged) → refuse with "applies to the at-root install; add --at-root" — never silently switch layout.
3. **Fresh nested install into a non-git target:** absent, or empty in the `EMPTY_OK_ALLOWLIST` sense → `mkdir -p` + `git init -q` the target as host, then the normal nested install. Non-empty and not a git repo → refuse, nothing written, hint "`git init` it yourself, or `--at-root`". Inside a git work tree but not its root → today's refusal, its hint also naming `--at-root`.
4. **Layout-already-in-place guard:** a bare fresh install into a target holding an **at-root** workspace (`scripts/workflow.py` + `works/`) refuses with "already installed at-root — use --update" and writes nothing. A target already holding a nested install keeps v49's idempotent exit 0, hint now plain `--update`.
5. **Convention for a host the installer just `git init`ed:** write `commit_convention` confirmed — `text` = this workspace's Commit Convention (`type(scope): summary`, imperative, no trailing period), `coauthor_trailers: allowed`, `inferred: null` — so `next` never nags `UNCONFIRMED` on the operator's own repo. An existing host keeps v49's infer-and-ask path. Inference (`_host_git("log", …)`, ~L569) must survive an unborn HEAD (failed `git log` = no history).
6. **At-root byte-for-byte unchanged behind `--at-root`** (P28 invariant (a) carried over): same writes, guards and output, apart from the flag name in hints. The upstream repo stays at-root; `installer/build.py` keeps its role.
7. **No migration.** Nothing converts an at-root install; `--update` on an at-root workspace behaves exactly as today.
8. **Tests, core only:** add `--at-root` to the 11 plain fresh `sh "$BOOT"` calls in `tests/retrofit_smoke.sh`, plus **one** new smoke test with probes (a) bare install into a new dir → host `git init`ed, nested `workflow/` + marker with a confirmed convention, host `git status --porcelain` empty; (b) bare install into an existing git repo → nested; (c) bare `--update` refreshes a nested install with no flag, and `--update --nested` still works; (d) bare `--update` on an at-root install stays at-root; (e) bare install over an at-root workspace refuses, nothing written; (f) contradictory flags refuse (`--update --at-root` on nested, `--at-root --nested`, `--force-empty-ok` without `--at-root`). Run the suite **once, alone in its own foreground Bash call**, and report the count against the baseline.
9. **Doc impact:** S1 and S2 each leave a one-line note — install modes and defaults in operations (`## Operator Runtime` unaffected) and in architecture's installer section. No `doc-new-version` in this phase.
- **Engine:** no change expected — `head_commit()` returns `""` on a host with no commit, so `host_anchors.created` is null and `phase-scope` diffs from the empty tree. S1 confirms this live and touches the engine only if something actually breaks.
