# Phase P29: Nested install by default

_Intent: see [intent.md](intent.md)._

## Objective

Make the nested personal install the installer's default layout everywhere (existing repos and fresh dirs, which get git init + nested workflow/); the at-root layout only on --at-root (or --into-existing); --update auto-detects the installed layout from its marker so /update-workspace needs no --nested; existing at-root installs keep updating at-root with no migration; ship as v50.

**Decisions S1 must hold.**
1. **Mode resolution: one function at the top of `main.py`, before `HOST, ROOT` are set** (today `NESTED` is read from env at import, ~L52). The wrapper exports `AT_ROOT`; `NESTED` is set only by an explicit `--nested`. Order: `--into-existing` or `--at-root` → at-root. `--update` → **detect**: `<target>/workflow/.agentic-nested.json` → nested; at-root workspace (`scripts/workflow.py` + `works/`) → at-root; both → refuse as ambiguous, naming both; neither → today's "no agentic workspace found". An explicit `--nested`/`--at-root` that **contradicts** the detected layout refuses in one line; a matching one is a no-op (keeps v49's `--update --nested` text working). Otherwise (fresh install) → **nested**.
2. **Wrapper conflicts:** `--at-root` + `--nested` → refuse. `--nested` + `--into-existing` → refuse (unchanged). `--force-empty-ok` without `--at-root` (or `--into-existing`, unchanged) → refuse with "applies to the at-root install; add --at-root" — never silently switch layout.
3. **Fresh nested install into a non-git target:** absent, or empty in the `EMPTY_OK_ALLOWLIST` sense → `mkdir -p` + `git init -q` the target as host, then the normal nested install. Non-empty and not a git repo → refuse, nothing written, hint "`git init` it yourself, or `--at-root`". Inside a git work tree but not its root → today's refusal, its hint also naming `--at-root`.
4. **Layout-already-in-place guard:** a bare fresh install into a target holding an **at-root** workspace (`scripts/workflow.py` + `works/`) refuses with "already installed at-root — use --update" and writes nothing. A target already holding a nested install keeps v49's idempotent exit 0, hint now plain `--update`.
5. **Convention for a host the installer just `git init`ed:** write `commit_convention` confirmed — `text` = this workspace's Commit Convention (`type(scope): summary`, imperative, no trailing period), `coauthor_trailers: allowed`, `inferred: null` — so `next` never nags `UNCONFIRMED` on the operator's own repo. An existing host keeps v49's infer-and-ask path. Inference (`_host_git("log", …)`, ~L569) must survive an unborn HEAD (failed `git log` = no history).
6. **At-root byte-for-byte unchanged behind `--at-root`** (P28 invariant (a) carried over): same writes, guards and output, apart from the flag name in hints. The upstream repo stays at-root; `installer/build.py` keeps its role.
7. **No migration.** Nothing converts an at-root install; `--update` on an at-root workspace behaves exactly as today.
8. **Tests, core only:** add `--at-root` to every plain fresh `sh "$BOOT"` call whose test expects the at-root layout — **4, not 11** (corrected by S1): Test 5 `$F` and `$H` (`--force-empty-ok`), Test 12 `$W`, Test 14 `$NS/seed`; Test 8's `$G --with-explain` is a rejection test and stays as is — plus **one** new smoke test with probes (a) bare install into a new dir → host `git init`ed, nested `workflow/` + marker with a confirmed convention, host `git status --porcelain` empty; (b) bare install into an existing git repo → nested; (c) bare `--update` refreshes a nested install with no flag, and `--update --nested` still works; (d) bare `--update` on an at-root install stays at-root; (e) bare install over an at-root workspace refuses, nothing written; (f) contradictory flags refuse (`--update --at-root` on nested, `--at-root --nested`, `--force-empty-ok` without `--at-root`). Run the suite **once, alone in its own foreground Bash call**, and report the count against the baseline.
9. **Doc impact:** S1 and S2 each leave a one-line note — install modes and defaults in operations (`## Operator Runtime` unaffected) and in architecture's installer section. No `doc-new-version` in this phase.

**Final flag shape (P29.S1; S2 writes the texts from this, not from the plan).**
- **Flags:** default = nested. `--at-root` = the committed at-root layout (fresh dir). `--into-existing` = at-root retrofit (`--at-root` with it is allowed, redundant). `--update` detects the layout. `--dry-run` with `--update` only. `--nested` = accepted, redundant (on `--update` it must match what is found). `--force-empty-ok` needs `--at-root` or `--into-existing` — **including on `--update`**, where v49 silently ignored it (a CHANGELOG migration-note item).
- **Wrapper refusals (one line each):** `--at-root and --nested are mutually exclusive`; `--nested and --into-existing are mutually exclusive (…)` (unchanged); `--force-empty-ok applies to the at-root install; add --at-root` (replaces v49's `--nested` + `--force-empty-ok` line); `--update and --into-existing` / `--dry-run` checks unchanged. Usage text: a short "By default the install is private and nested …" paragraph, `--at-root`, `--force-empty-ok` "With --at-root", `--into-existing` "At-root retrofit", `--update` "the layout … is detected", `--nested` "Accepted and redundant"; closing line "Requires python3 (>= 3.8), and git for the default nested install. A fresh install never overwrites an installed workspace: refresh one with --update." (S2's final pass.)
- **Resolution (`resolve_layout()` in `installer/main.py`, before `HOST, ROOT`):** `--into-existing` → at-root. A target holding `.agentic-nested.json` **itself** (a nested install's `workflow/`), on any `--update` or a fresh nested install → refuse: `<T> is the workflow/ directory of a nested install (it holds .agentic-nested.json): run the installer on the host repo's root, <parent>, instead (nothing written).` (S1 addition: v49's plain `--update` there would have written `CLAUDE.md` and `.claude/` into `workflow/`.) Fresh: `--at-root` → at-root, else nested. `--update`: `nested_here` = `<T>/workflow/.agentic-nested.json` (lexists), `root_here` = `scripts/workflow.py` + works (`works/state.json` or an active `phase.json`). Both, no flag → `<T> holds both a nested install (<T>/workflow/.agentic-nested.json) and an at-root workspace (<T>/scripts/workflow.py plus works/): the layout to update is ambiguous.` + `Re-run with --update --nested or --update --at-root to say which one to refresh (nothing written).`; both + a flag → the flag decides. Nested only + `--at-root` → `--at-root given, but <T> holds a nested install (workflow/.agentic-nested.json); drop the flag.` At-root only + `--nested` → `--nested given, but <T> holds an at-root workspace (scripts/workflow.py plus works/); drop the flag.` Neither → at-root: `no agentic workspace found here to update.` + `A new install is just: sh bootstrap_agentic_workspace.sh <dir> (the private nested layout, the default), or --at-root / --into-existing for the committed at-root layout.` (replaces both v49 hint lines).
- **Fresh nested preflight, in order:** (1) at-root workspace already at the target → `<T> already holds an at-root agentic workspace: use --update to refresh it (a fresh install would put a second, nested one beside it).` (runs **before** the git check, so the advice is right on a git-less machine; the upstream repo itself refuses here, verified live); (2) no git → `the default (nested) install needs git on PATH (the host is a git repo, and workflow/ becomes a nested one): install git, or use --at-root.` (update: `…: install git, then re-run.`); (3) `<TARGET> exists and is not a directory.`; (4) **init** (`nested_init_host`): absent, or empty in the `EMPTY_OK_ALLOWLIST` sense with no `.git` and in no work tree → `mkdir -p` + `git init -q`, `HOST_INITED`. An **absent** target whose nearest existing ancestor is inside a work tree is refused like an empty dir there (S1 reading of decision 3; see `## Operator Questions`); (5) not a work tree: `<HOST>/.git exists, but git does not read <HOST> as a work tree: repair the repo (then re-run), or install the committed at-root layout with --at-root` / `<HOST> is not a git repo and is not empty: run git init there first (then re-run), or install the committed at-root layout with --at-root`; (6) below a work tree's root: `the nested install goes at a git repo's root, and <HOST> is inside the work tree of <top>: re-run with <top> as TARGET_DIR, or install the committed at-root layout with --at-root.` + for an empty/absent target `To make <HOST> a repo of its own instead, run git init there first (then re-run).`; (7) P28's checks unchanged; already nested → exit 0 `… already installed -- use --update to refresh it.` Update-side texts: `a nested install's host must be the root of a git work tree, and <HOST> is not inside one (nothing written).` / `… is inside the work tree of <top> (nothing written).`; incomplete install → `the nested install here is incomplete (an update needs workflow/.agentic-nested.json and workflow/scripts/workflow.py).` + `Restore them from the nested repo's own history (git -C workflow status), then re-run (nothing written).`
- **Init undo:** every `_nested_refuse` (and any exception) before the first write removes the `.git` this run created and `rmdir`s each directory it created (deepest first, only if empty); the operator's own files are never touched. From `ROOT.mkdir` on, the init is kept.
- **Initialised-host convention:** `{"inferred": null, "confirmed": true, "text": "type(scope): summary -- imperative, no trailing period", "coauthor_trailers": "allowed"}` (passes `nested_marker_problems`). An existing host keeps v49's infer-and-ask path; inference on an unborn HEAD (`git log` exit 128) yields `inferred: null`, verified live. `--update` keeps a confirmed convention, so an initialised host stays confirmed.
- **Banners:** update `Update complete (--update) at <HOST> (nested, detected)` / `DRY RUN (--update --dry-run) at <HOST> (nested, detected) -- nothing written.`; install `Installed the agentic workspace privately into the host repo at <HOST>` (no `(--nested)`). Initialised host only: `  host: a new git repo -- the installer ran git init there, and it has no commits yet`; `  host commit convention: confirmed for the new repo -- this workspace's own (<text>), coauthor_trailers=allowed`; `The installer made no git commits: the host has no commits yet, and the workspace's files in it stay untracked.`; `The new repo's commit convention is recorded; … nested-convention shows it (--confirm --text "..." --trailers allowed|forbidden changes it).`; the "Any remote for workflow/ stays inside your company's org" line is dropped. Step 1 (first nested commit) is unchanged. At-root banners are unchanged.
