# CLAUDE.md — developing bootstrap_agentic_workspace.sh

This repo **ships the agentic workspace**: the single-file installer `bootstrap_agentic_workspace.sh` and its sources. The workspace that plans and records the work on it is a **private multi-repo host** in this repo's parent folder: `../workflow/` (its own git repo), `../CLAUDE.local.md` and `../.claude/`, none of it tracked anywhere; this repo is registered there as `bootstrap_agentic_workspace`. Start Claude Code in that folder, never here, and drive the workspace from there with `python3 workflow/scripts/workflow.py <command>`. Commit workflow state with `git -C workflow …` from the host, never in this repo.

Paths and commands in this file are relative to this repo's root; from the host, prefix them with `bootstrap_agentic_workspace/` (or use `git -C bootstrap_agentic_workspace …`).

## Layout

- `payload/`: the shipped sources, each at its **emit path with the first component undotted**: `payload/claude/{skills,agents,settings.json}`, `payload/scripts/workflow.py`, `payload/works/templates/`, `payload/executors.toml` (the adopter seed's source), `payload/github/workflows/workspace-ci.yml` (the adopter CI seed), `payload/gitattributes`, and `payload/contract.md` (the shipped `CLAUDE.md`). Never put a dotted name or a `CLAUDE.md` under `payload/`: Claude Code or GitHub would load it.
- `installer/`: `build.py`, `main.py`, `wrapper.sh`, `payloads/doc_bodies/`.
- `tests/retrofit_smoke.sh`: the release smoke suite.
- `changelog.d/`: pending release notes, one fragment per branch (its `README.md` gives the format). Only `--release` turns them into a version.
- **The workspace's installed copies (`.claude/skills/`, `.claude/agents/`, `CLAUDE.local.md`, `workflow/`) live in the host folder above this repo, untracked. Never edit them**: an edit there shows no diff and is lost at the next `--update`. Edit `payload/`, rebuild, then refresh.

## Rules

- After editing `payload/**` or `installer/**`, run `python3 installer/build.py` and commit the rebuilt `bootstrap_agentic_workspace.sh` in the same commit. `.githooks/pre-commit` enforces `--check` (register once per clone: `git config core.hooksPath .githooks`, which also arms the release guards below).
- **The version is stamped as work lands on `main`, never on a branch.** A branch or slice never touches `WORKSPACE_VERSION` or `CHANGELOG.md`'s numbered sections; it writes its notes in `changelog.d/<slug>.md` (line 1 `# <one-line summary>`, then the bullets, including a `**Migration notes.**` line; format in `changelog.d/README.md`). So two parallel branches never renumber each other.
- **Landing a branch on `main`:** before the local landing, the branch is pushed and opened as a **draft PR** for the owner's read on GitHub (the `pr` skill, when the phase's review passes). At the operator's `accept`, the close (the `pr` skill's `reference/close.md`) re-reads the draft and flips it Ready (`gh pr ready`); then it lands exactly as below, and pushing `main` with the merged head closes the PR as merged. **Never use GitHub's merge button:** it runs no `--release`, so the fragment would land unstamped and CI's fragment guard would fail the push to `main`. The landing: `git merge --no-ff --no-commit <branch>` → `python3 installer/build.py --release` → `git add -A CHANGELOG.md installer/main.py bootstrap_agentic_workspace.sh changelog.d` → `git commit -m "build(release): workspace v<M> — <summary>"` (`--release` prints `released=v<M>` and the subject). It stamps `M = N + 1` into a `## v<M> — <date>` section holding every pending fragment (by file name), sets `WORKSPACE_VERSION = M`, deletes the fragments and rebuilds the artifact, which also settles an artifact merge conflict. It refuses off `main`, with no fragment, with a fragment missing its summary or Migration notes line, and when `WORKSPACE_VERSION` is not the top `## v<N>`. A release made on `main` directly: write the fragment, run `--release`, commit the same way. Then push `main`.
- **Guards against a forgotten stamp:** on `main`, `.githooks/pre-commit` and `.githooks/pre-merge-commit` (git's automatic merge commits) refuse a commit that holds a fragment, and CI fails a push to `main` that carries one. Never hand-edit `WORKSPACE_VERSION` or add a numbered CHANGELOG section. The smoke suite still checks that the version, the top CHANGELOG section and a fresh install's marker agree.
- Refresh the host's install from this build: from the host folder, `sh bootstrap_agentic_workspace/bootstrap_agentic_workspace.sh --update .`, then commit the refresh with `git -C workflow` at the host.
- This repo's commits follow the custom recorded with `nested-convention --repo bootstrap_agentic_workspace` (Conventional Commits, a component scope, **no phase or slice IDs**, `Co-Authored-By` allowed); the IDs live in the nested repo's commits.
- Run `bash tests/retrofit_smoke.sh` **alone** in its shell call, never chained.
- CI here is `.github/workflows/upstream-ci.yml` (build parity + smoke). The shipped adopter CI seed never runs in this repo.
