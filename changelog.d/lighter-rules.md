# Lighter rules: a one-screen contract and the agent's own browser, playwright-cli

- **The agent's browser is `playwright-cli`, driven from the shell.** Every real-browser check (verification, the review's walkthrough, design fidelity, a PR body's screenshots) runs on `@playwright/cli` 0.1.25: headless, on a throwaway profile, never the operator's. The agent installs it (`npm install -g @playwright/cli@0.1.25`, then `playwright-cli install-browser chrome-for-testing` when no browser is found), starts, restarts (`kill-all`) and closes it itself; the shipped settings allow `Bash(playwright-cli:*)`, `Bash(npm install -g @playwright/cli:*)` and `Bash(npm i -g @playwright/cli:*)`, so no prompt stops it. A saved sign-in is a `state-save` file the operator makes once, named in `## Operator Runtime`'s new `Saved sign-in:` line; only a credential, a sign-in or a paid account stops a run. The dedicated Chrome profile, its recorded id, the select-first step and the "third halt" are retired, and `slice-executor` no longer carries the Claude in Chrome tools: Claude in Chrome is used only when you ask an agent to use your own browser. The procedure lives in `design-cowork`'s `reference/build.md`.
- **The contract fits one screen.** `CLAUDE.md` drops from 12 KB to under 4 KB (≤ 60 lines): the four invariants you signed (nothing is pushed, merged or paid for without your word; a sign-off is your literal words; your own work is never touched; reports are truthful), seven named principles to steer by (prove it works, subtract before you add, settle by a run, finish line first, stop what you start, take your own recommendation, ask don't archive), the correction ladder (product code, then a type or lint, then a test or check, a rule file last), and a rule table whose every row names what enforces it: an engine refusal, a settings rule, a CI step or a smoke check (the smoke suite now holds the contract to 4,096 B). The read order, the canonical-state list, the status lists, the design, review and parallel procedures and the doc-consolidation duty left it: the skills, the executor card and `workflow.py --help` carry them. A multi-repo host's `CLAUDE.local.md` block is trimmed to what a host needs, points a bare host session at each repo's verification skill (`<repo>/.claude/skills/`), and points at the `parallel-phase` skill for worktree mechanics.
- **Migration notes.** Run `npm install -g @playwright/cli@0.1.25` once per machine (the `update-workspace` skill now does it). In your operations doc's `## Operator Runtime`, retire the `Agent's Chrome deviceId:` line, set `Browser instrument for the agent:` to playwright-cli and add `Saved sign-in:` (the seed's shape in `installer/payloads/doc_bodies/operations.md`), with `doc-new-version`. Claude in Chrome (the extension, `/chrome`, the agent profile) is no longer needed for agents. `--update` replaces the contract (`CLAUDE.md`, or `workflow/CLAUDE.workspace.md` in a nested install) and the managed `CLAUDE.local.md` block; if your own rules quoted the old contract's sections (Hard Rules, Canonical State, Commit Convention), point them at the skills instead: commits follow the `commit` skill (`type(scope): summary`), and no `## Doc impact` note or docs phase is asked for any more.
