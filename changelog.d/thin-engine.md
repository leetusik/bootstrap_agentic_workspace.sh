# A thin engine: fewer commands, five refusals, the rest advice

- **The core flow is pinned.** A new smoke test drives a toy phase through the commands that stay (the phase and slice lifecycle, a section read and append, a typed stop, the acceptance gate, `pr-branch`'s dirty-tree refusal, `validate`, the pass and the archive), so the renames that follow keep that behaviour.
- **The docs subsystem is retired.** `docs`, `rebuild-docs`, `doc-new-version`, `docs-debt`, `docs-consolidated` and `parallel-consolidated` are gone, with the consolidation debt behind them: a passing review stamps nothing, `parallel-start` stamps no `consolidation`, `next` and `validate` print no `consolidation_owed=`, `stale_docs=` or oversized-section line, `new-phase --consolidates` is gone, and archiving never holds a phase for doc debt. `docs/current/*.md` are plain files that agents edit in place; a fresh install seeds the five bodies with no frontmatter, no `docs/index.json` and no versions. The `doc-new-version` skill is retired (`--update` flags an unchanged copy stale), and the phase notebook template drops `## Doc impact` (`phase-section` still reads and appends to it in older notebooks).
- **`rotate-backlog` only archives.** Its result is `rotate=archive` (or `rotate=refused` on a parallel stream); the docs-phase proposals and the stops that guarded them are gone.
- **`run-phases` and `parallel-skip` are retired.** `next` is the one pointer; the resume card drops its parked-run line.
- **Loop phases are retired.** The twelve `loop-*` commands, `new-phase --loop`, the `run-loop` skill, the `cycle` slice kind and its playbook, the charter template, the `screen` route row and the loop's `.gitattributes` union lines are gone, with their hooks in the core: the per-loop event files, the hidden loop REVIEW, the loop guard on a pass, the checkpoint merge in `parallel-gate` and `next`'s checkpoint `merge_ready=`. The contract drops its loop rows. A `phase.json` that still carries a `loop` block reads as an ordinary phase.
- **The engine is flat modules.** `scripts/workflow.py` is now the entry (the parser and the dispatch) beside `wf_store.py` (where the state is, paths, ids, events, phases, slices, the notebook, `next`, review, the gate, rebuild, validate, archive), `wf_git.py` (PRs, the parallel worktrees, the repo registry, `phase-scope`), and the parts moved as they were: `wf_design.py`, `wf_agenda.py` (agenda and deferred jobs), `wf_cloud.py` and `wf_adapter.py` (executor routes, `sync-agents`, the dispatch meter, the compaction hook). `wf_store` imports none of the others; what it calls in them is listed in its `SEAMS` and bound by the entry. No command, flag or output changed. The engine sets `sys.dont_write_bytecode`, so no `scripts/__pycache__/` appears beside it on any Python.
- **The engine finds its workspace from anywhere.** In order: its own parent when that holds `works/` (every installed copy, as before); the folder `WORKFLOW_ROOT` names (a nested host's `workflow/` when it names the host); the first folder up from the current directory holding `workflow/.agentic-nested.json` or `works/phases/`. With none it exits 2 with one line, `no workspace found from <cwd>; run from inside one or set WORKFLOW_ROOT`, and never writes into its own folder (an older engine copied outside a workspace wrote `works/` there). `WORKFLOW_CMD` overrides the command the hints print; an engine outside the workspace prints its own path from the host. The compaction hook's walk to the session's workspace follows the same rule.
- **The installer ships every engine module.** Fresh installs, `--into-existing` and `--update` write every `scripts/*.py` the build embeds (`--update` adds the new ones); a retrofit aborts on a foreign file at any of those paths, as it did for `scripts/workflow.py`.
- **The core verbs.** Sixteen commands become four verbs, and `next` stays: `phase new|status|archive|rotate|reopen|scope|rounds` (was `new-phase`, `set-phase-status`, `archive-phase`/`archive-all` as `phase archive <P>`/`phase archive --all`, `rotate-backlog`, `reopen-phase`, `phase-scope`, `parallel-plan`), `slice new|start|finish|status|deps` (was `new-slice`, `start-slice`, `finish-slice`, `set-slice-status`, `set-slice-deps`), `section` (was `phase-section`) and `check` (was `rebuild` then `validate`; `check --no-rebuild` validates only). Arguments and outputs are unchanged; an old name exits 2 with argparse's usage error. `--help` lists 56 commands (was 68).
- **Four refusals are advice now.** `slice new` makes an unknown `--kind` with one `advice:` line naming the set (it routes on the high row); `slice finish` on a decomposition that leaves a middle slice undeclared finishes and prints one `advice:` line per slice (it runs alone); `section ... --replace` on Operator Questions (or an older Doc impact), and `--entry K --replace|--remove` there or a `--remove` in Decisions, write and print one `advice:` line; the notebook budget's step reads `advice: move long entries ...` (its required form is gone). `promote-deferred` still refuses an unknown kind before it mints a phase.
- **A pending stop must be typed.** `slice status <S> pending` without both `--stop-kind` and `--on-words` is refused, nothing written (it used to write an untyped stop with a warning).
- **`section` takes any heading.** A write to a heading the notebook lacks (`section <P> Walkthrough --append`) creates it at the end, before `## Now`; before, it exited 1 with `unknown section`. A read of a missing heading still exits 1.
- **`check`, in the installer and the CI seed.** Install and `--update` end with `check`; a fresh CI seed runs `check --no-rebuild` in a job named `check`; a worktree stream refreshes the default checkout with its `check`. The contract drops the kind, dependency and append-only rows and points the typed-stop and state rows at `slice status` and `check`. The `rebuild-workflow` skill is retired (its two lines are `check`): 18 skills. The generated `## Slices` line now names `check`, so the first rebuild after the update rewrites that one line in every active notebook.
- **The decompose playbook names the smoke cadence:** a slice runs the repo's fast check (the tests its change touches); the full check runs once per phase, before the PR or in the background on a slice's commit; each repo names both commands in its rules or verification skill.
- **Migration notes.** A loop's `/run-loop` and `loop-*` commands are gone, and nothing replaces them. `--update` flags an unchanged `run-loop` skill, `do-whole-phase/playbooks/cycle.md` and `works/templates/charter.md` stale; an executors.toml `[claude.screen]` section is now an unknown route (delete it); the `works/phases/**/loop/*.jsonl merge=union` lines an older install added to `.gitattributes` stay and are harmless. The rest is to be written when the renames land. The engine is now several files: an install holds `scripts/workflow.py` plus `scripts/wf_*.py`, and `--update` adds them; run the engine as before (`python3 scripts/workflow.py ...`), and copy the whole `scripts/` folder, never `workflow.py` alone. A script that loaded `workflow.py` with `importlib` and patched a name inside a part patches that part's module now (`sys.modules["wf_cloud"]`, `wf_agenda`, ...). **The command renames:** the old-to-new table is the first bullet above (`phase archive --all` for `archive-all`, `check` for `rebuild`, `check --no-rebuild` for `validate`); there is no alias, so an adopter's own scripts, hooks or notes that call an old name must move to the verb. An existing at-root CI seed (`.github/workflows/workspace-ci.yml`, seed-once) still runs `python3 scripts/workflow.py validate` and fails until you change that line to `check --no-rebuild`. `--update` flags an unchanged `rebuild-workflow` skill stale. A `slice status <S> pending` without `--stop-kind` and `--on-words` is now refused.
