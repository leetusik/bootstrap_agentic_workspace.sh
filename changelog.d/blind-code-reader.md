# A blind code reader reads every product change before it ships, and plans prove their claims

- **The `code-reader` agent.** A new managed agent file, `.claude/agents/code-reader.md`, reads one code change cold: the diff over the product pathspec and the files at head, never the workspace's records (`intent.md`, `phase.md`, plans, results). It reproduces what it suspects and writes one findings file (`topics/code-read.md`; `topics/code-read-<repo>.md` per repo on a multi-repo host), each finding `C<nn> · lens · severity · confirmed|suspected`, with a coverage list of what it probed, read and did not read. It runs on a new route row, `code` (opus @ high), dispatched from `executor-route --code` and overridable as `[claude.code]` in `executors.toml`; `sync-agents` now writes six managed agent files.
- **The phase review rules on the reader first.** A phase whose `phase-scope` lists product files gets the code reader before its review is dispatched, and the review's plan names the findings file. The review re-runs each `confirmed` finding's reproduction, probes or routes each `suspected` one, and records one ruling per finding in `result.md` under `## Code reader` (upheld → a finding whose cases become the fix slice's acceptance matrix, or rejected with the reason). It may not pass with a finding it has not ruled on, and returns a new `code_read` field (the findings file, then counts upheld / rejected / routed, or `n/a (0 product files)`). A re-review round rules the same way on the reader's re-read, `topics/code-read-r<n>.md`.
- **Plans list their claims and contracts.** An implementation or fix slice's `plan.md` carries `## Claims and contracts`: each never / always / at-most / only / refuses / cap / guard claim the slice makes, and each external contract it relies on with its source (or `unread`). The executor proves each claim with a check seen failing first in the real runtime and reports it in a new verdict field, `claims` (the claim, how it was seen failing, the command that passes). The review treats a listed claim with no failing-first check, or one proven by argument, as a finding.
- **`/read-code`.** A new skill, the 21st: blind-read a product change made outside a phase before it is pushed. With no argument it reads the current branch's unpushed commits plus its uncommitted changes (against its upstream, else the default branch); `<base>..<head>` or one ref names another range. It dispatches the `code-reader` on the product pathspec, writes the findings outside the repo, and reports them for you to decide on. The shipped contract gains the rule that goes with it: a blind `code-reader` reads each product change before it ships, unless you say skip (a phase's diff before its review, any other change before its push).
- **`phase-scope` prints its pathspec.** `phase-scope <P>` now prints the git pathspec it read the product files with as a `pathspec=` line (a `pathspec` key in `--json`; on a multi-repo host one `repo=<name> pathspec=` line per repo and the host's), quoted to paste after `--` in a POSIX shell, and `phase-scope --pathspec` prints the same with no phase. The reader dispatches and `/read-code` pass that value instead of writing one by hand.
- **Migration notes.** Run `--update`, then start a fresh Claude Code session: the new `code-reader` agent file is only dispatchable from a session started after it lands. `[claude.code]` is a new, optional `executors.toml` row; an updated install keeps its existing `executors.toml` untouched, so it gains no commented example table, and the `code` row runs on the engine default (opus @ high) until you add one. Slices planned before the update carry no `## Claims and contracts` and are not held to it. Nothing else beyond `--update`.
