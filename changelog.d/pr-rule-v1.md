# Every phase ends in a short draft PR, read by a fresh-eyes reader and opened on the operator's push

- **The PR rule.** A phase is one branch per repo it changes and one draft PR each. `DECOMP`'s end records the branches (`pr-branch <P> --name <b> [--repo <name>] [--base <ref>]`, which cuts the branch or records the checked-out one); `new-phase` stamps an empty `pr` block in `phase.json`. The review writes each PR body as a review lens and returns `pr_bodies`; a new fifth agent, `pr-reader` (route row `reader`, opus @ high, `executor-route --reader`), reads the diff and the body cold, as a teammate would, and its findings get one body revision. Then one `push` stop holds the pass: the acceptance gate itself when it is required, else the `REVIEW` slice `pending` (`decision`). On the operator's `push` the new `pr` skill pushes, opens the drafts, and the orchestrator records each URL (`pr-record <P> --url <url>`). `review-phase --verdict pass` refuses, writing nothing, while a recorded branch has no URL, or while a block with no branch faces committed product files; `pr-record <P> --waive --note "why"` covers a phase whose change is not worth a PR. `next` prints `pr_branch=`, `pr_push=waiting` and `pr_waived=` lines; `/do-whole-phases` parks a waived gate's `push` stop like an open gate, and the operator's `push` resumes it.
- **The body.** The repo's own PR template keeps its headings and ours fills the gaps; the default is Summary · Review (what to decide, what to check, the risks, what to do before merging) · What is changed (by idea, never per file, with 2–3 lines on how it was tested) · Why · Related issue. `pr-check <P> [--body <path>]` measures it: 1,500 reading chars before the first section after Review, 3,500 visible, 6,000 whole; no phase or slice IDs, `workflow/` paths or workspace file names (a percentile is written `p95`); the headings in order. The `pr` skill's `reference/body.md` carries the visual rule (a diagram or screenshot only where it beats prose) and the prose rules.
- **Size and splits at review.** `pr-check` counts changed lines (a target of 400, a flag over 1,000), skipping generated files, lockfiles, deletions and binaries; tests count. Size never splits a phase: the review may split an over-flag branch into an in-repo stack or a cross-repo series (`reference/split.md`).
- **Team PR rules at install and update.** The installer reads the team's tracked rule files (PR templates, CONTRIBUTING, CODEOWNERS, PR lines in AGENTS/CLAUDE files, PR agent skills) and prints a `team PR rules:` line plus one `PR-rules conflict:` line per point where they disagree with ours. It records nothing; `/update-workspace` shows the conflicts and records only those the operator decides (`pr-rules-decide --rule … --choice team|ours`). The team wins wherever it speaks.
- **At-root installs fold their state in PR diffs.** A fresh at-root install, and `--update` once, add `linguist-generated=true` lines for `works/**`, `docs/versions/**`, `docs/current/**` and `docs/index.json` to `.gitattributes`, so GitHub folds the workspace's state and `pr-check` skips it. A nested install's state never enters a host PR.
- **A symlinked `.claude/skills` stays hidden.** When the host's `.claude/skills` is a symlink inside the repo (say to `.agents/skills`), a nested install's skill copies land in the resolved directory; the exclude lines, the tracked-target check and the post-write verify now use the resolved paths too, and the banner names where the copies sit. The team's files and the link are never touched.
- **Fixed: `phase-scope` and passing reviews crashed on a nested phase off the default branch.** Since v91 a second `_is_ancestor` shadowed the first, so a nested phase whose host branch had left the default branch hit a `TypeError` in `phase-scope` and in `review-phase --verdict pass`. The loop's helper is now `_ref_is_ancestor`.
- **Migration notes.** Run `--update`, then **start a fresh Claude Code session** so the new `pr-reader` agent loads (a review that needs it stops `pending` until you restart). At the next `/update-workspace`, decide any team-PR-rule conflicts it shows, or leave the team's rule in force. Phases created before this version carry no `pr` block and are not guarded. If your recorded host convention says "no PR" or "work on main", re-record it with `nested-convention --confirm`. Draft PRs on private repos need a paid GitHub plan; without one the `pr` skill retries once and opens a plain PR.
