# Workspace sync: a linked checkout keeps its workspace in hi2vi

- **Cloud mode at the command boundary.** A checkout is linked exactly when `.hi2vi/link.json` exists beside `works/` (server, org and project id; never a key). Without it every command runs exactly as before: nothing is read, no socket is opened. With it, each engine command first pulls what changed in hi2vi since `.hi2vi/base.json`'s head (a fast-forward; the generated files are rebuilt after a pull), runs unchanged against the disk, then sends every truth-file difference as one all-or-nothing batch and records the new revisions in `base.json`.
- **The truth set** is `works/**` and `docs/**` minus the generated files, `works/templates/`, the version marker, folders whose `.gitignore` is `*` and temp files. Files written outside the engine (an agent's `plan.md`, `result.md`, topics) ride the next command's batch marked `carried`; the command's own changes are marked `command`. Equal content sends nothing. `works/events.jsonl` and a loop's union logs go as appended lines, never as revisions; a folder move (archive, a deferred job's drop or promote) goes as moves paired by content, so a file's history follows it. Every batch also carries the freshly rendered `works/state.json` and `works/index.json`.
- **The client** is the standard library only: `https://` required (plain `http://` only to `localhost`, `127.0.0.1`, `::1` and `*.localhost`), 10 s timeouts, redirects never followed, the workspace key read from `$XDG_CONFIG_HOME/hi2vi/workspace-keys.json` and sent only as a Bearer header.
- **Migration notes.** None: an install without `.hi2vi/link.json` is unchanged.
